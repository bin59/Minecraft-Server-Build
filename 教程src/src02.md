# 二、运维监控与面板

## MCSM (MCSManager)

MCSM 是基于 Web 的游戏服务器管理面板，使用者（服主/管理员）通过浏览器完成实例创建、启停、文件管理与终端操作，无游戏内命令。

### 命令 / 操作（Web 面板）

- **创建实例**：面板主界面 → 快速开始 → 创建 Minecraft 服务器 → 选择一键开服/手动上传。
- **启动 / 停止实例**：进入实例 → 终端/控制台页面 → 点击开启实例/启动 或停止按钮。
- **文件管理**：实例 → 文件管理页面，浏览、上传、编辑服务端文件（如 eula.txt、server.properties）。
- **控制台命令**：在终端/控制台直接输入服务端命令并查看实时日志。
- **链接已有文件夹（不重新上传）**：新建实例 → Java版Minecraft游戏服务端 → 无需文件或选择已存在文件 → 在"服务端文件目录"填写完整路径 → 填实例名与启动命令后确认。
- **节点管理（分布式）**：左侧 节点管理 → 新建节点 → 填写节点名称、节点地址（远端电脑局域网 IP）、节点端口 24444、API 密钥 → 连接。

### 权限节点

MCSM 采用多用户细粒度权限体系（管理员 / 普通用户）。普通用户仅能访问被分配给自己的实例，无法触碰其他实例或宿主文件。

### 典型工作流

1. **首次开服**：注册管理员账号 → 新建实例（一键开服选版本）→ 同意 eula.txt → 启动实例 → 控制台看到 Done 即成功。
2. **接管已有服务端**：用"链接已有文件夹"方式，直接指向本地已存在且完整的服务端目录，避免上传大文件。
3. **跨机管理**：电脑 A 运行 Daemon（端口 24444）并记下 key；电脑 B 运行 Panel，在节点管理中添加电脑 A 的 Daemon 节点，即可远程启停。

## EasyBot

EasyBot 将 Minecraft 服务器与 QQ 群打通，实现群聊/游戏内聊天双向同步、群内执行命令、玩家 QQ 绑定与 @ 提醒。提供少量游戏内命令。

### 命令

| 命令 | 说明 | 参数 / 示例 |
| --- | --- | --- |
| `/bind <验证码>` | 玩家绑定自己的 QQ 账号（需服主已启用 allow_bind） | `<验证码>` 由服主提供；示例：`/bind 123456` |
| `/ebot reload` | 重载 EasyBot 配置并重新连接主程序 | 无参数；示例：`/ebot reload` |

**功能说明（连接成功后自动生效，无需命令）**：QQ 群 ↔ 游戏内聊天双向同步；群内 @ 某玩家时，该玩家游戏内收到标题提醒；绑定后支持白名单/验证。

### 权限节点

- `/bind` 受服务端 allow_bind 开关约束（本服当前启用），玩家可自行使用。
- `/ebot reload` 为管理类命令，默认需 OP/管理员权限。

### 典型工作流

1. **玩家绑定 QQ**：玩家进服后在游戏内执行 `/bind <验证码>`，绑定成功后实现 QQ↔游戏双向同步与白名单验证。
2. **日常聊天同步**：绑定/连接正常后，群消息与游戏内消息自动互相同步。
3. **@ 提醒**：群内 @ 某玩家 → 该玩家在游戏内收到标题提醒。
4. **连接异常处理**：若 MC 服务器先于 EasyBot 主程序启动导致连接失败，在游戏内执行 `/ebot reload` 重连。

## OPanel

OPanel 是自带完整 Web 前后端的 Minecraft 服务器图形化管理面板，管理员浏览器登录即可管理服务器，无游戏内命令。

### 操作（Web 面板）

访问地址 `http://服务器IP:3000`，使用 accessKey 鉴权登录。面板内可执行的功能：
- **仪表盘**：查看在线人数、TPS、内存等服务器总览。
- **玩家管理**：踢人、封禁、白名单管理、修改玩家权限。
- **存档管理**：上传 / 下载 / 删除 / 启用存档。
- **插件管理**：启停插件、查看插件详细信息。
- **后台终端**：网页内发送消息或执行服务端命令，支持彩色日志、Tab 补全、历史记录。
- **背包编辑**：可视化编辑玩家背包。
- **内置地图**：面板内查看游戏内实时地图（需在面板设置中手动启用）。
- **游戏规则编辑器**：切换 gamerule 而无需输入命令。
- **MCP / Open API**：可接入 AI 助手或通过 Open API 对外展示服务器状态。

### 权限节点

无游戏内权限节点；面板通过 accessKey 鉴权，管理员浏览器登录即拥有全部管理权限。

### 典型工作流

1. 浏览器访问 `http://服务器IP:3000`，输入 accessKey 登录面板。
2. **日常监控**：仪表盘查看 TPS 与内存；后台终端查看彩色日志。
3. **玩家管理**：在"玩家管理"中踢人、封禁、加白名单或调整权限。
4. **插件/存档维护**：插件管理启停插件；存档管理上传下载备份。

### 版本信息

最新版本 2.2.9（2026-11-07）/ 查证日期 2026-11-07 / 来源 https://github.com/opanel-mc/opanel

## spark

spark 是高性能服务器性能分析工具（LuckPerms 作者开发），用于实时监控 CPU、TPS、内存，并通过采样生成可分享的火焰图报告定位卡顿。

### 命令

| 命令 | 说明 |
| --- | --- |
| `/spark` | 查看基本信息与使用率 |
| `/spark health` | 服务器健康报告（TPS、CPU、内存、磁盘等） |
| `/spark tps` | 查看 TPS |
| `/spark profiler start` | 开始性能分析采样（参数见下） |
| `/spark profiler stop` | 停止采样并获取分析报告链接 |
| `/spark profiler open` | 打开最近一次分析报告 |
| `/spark gc` | 查看 GC（垃圾回收）信息 |
| `/spark ping` | 查看玩家延迟（RTT） |

**`/spark profiler start` 常用参数**：
- `--thread '*'`：全线程采样（默认只采样主线程，看网络须加此项）。
- `--timeout <秒>`：采样时长，示例 `--timeout 120`。
- `--only-ticks-over <数值>`：仅采样 TPS 低于该值的时段。

**查看网络线程的规范流程**：`/spark profiler start --thread '*' --timeout 120` → 让目标玩家复现问题 → `/spark profiler stop` 拿到报告链接 → 在 spark.lucko.me 打开，将 Group by 切到 Thread，查看 Netty Server IO、Geyser IO、TAB 等线程的 CPU 占比。

### 权限节点

- `spark`：基础权限，默认仅 OP 拥有。
- 子权限可按需细化授予，如 `spark.profiler`、`spark.health`、`spark.tps`、`spark.gc`、`spark.ping` 等。

### 典型工作流

1. **日常监控**：`/spark tps` 看实时 TPS；`/spark health` 看整体健康度；`/spark ping` 看单玩家延迟。
2. **定位卡顿**：`/spark profiler start --thread '*' --timeout 120` → 让玩家复现卡顿 → `/spark profiler stop` 取得报告链接 → 在线报告按线程分析热点方法。

### 版本信息

最新版本 1.10.187（2026-09-19，面向 MC 26.x）/ 查证日期 2026-09-19 / 来源 https://modrinth.com/mod/spark

## bStats

bStats 是插件普遍接入的匿名使用统计服务，启动后被动上报服务器数量、MC 版本、地区、已装插件等聚合数据，不收集玩家个人信息。

### 命令

无使用者可直接使用的命令（纯服务端组件）。

### 典型工作流

组件随服务器启动被动运行，每日将匿名统计数据上报至 bStats.org 公共仪表盘。服主若不愿参与统计，可在 plugins/bStats/config.yml 中将 enabled 设为 false 以退出。

### 版本信息

最新 Metrics 库版本 3.2.1 / 查证日期 2026 / 来源 https://github.com/Bastian/bstats-metrics
