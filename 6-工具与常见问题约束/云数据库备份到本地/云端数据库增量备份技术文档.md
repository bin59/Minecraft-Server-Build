## 1. 文档目的

本系统实现将**云端 MariaDB 数据库**定期增量备份至**本地 MySQL 数据库**。

核心需求：
- 云端只保留最近 **30 天**数据（自动清理旧数据）
- 本地必须**保留全部历史数据**（只增不删，不受云端清理策略影响）

本系统通过「按主键增量合并」机制实现该目标，并配置 Windows 计划任务每日自动执行。

```
              │                                          │
              │  增量同步（每天 04:30）                     │
              └───────────────────────────────────────────┘
                           Windows 计划任务
                           DBCloudSyncLocal
```

**数据流说明**：
1. 同步脚本连接云端，读取各表主键最大值；
2. 对比本地对应表主键最大值，仅导出云端新增部分；
3. 用 `INSERT IGNORE` 追加到本地；
4. 云端后续删除的旧数据，本地不做任何删除操作。

## 4. 同步策略设计

### 4.1 核心原则

- **本地只增不删**：脚本从不执行 `DELETE` / `TRUNCATE` / `DROP`（首次修复空表除外）；
- **按主键增量**：每次仅同步主键值大于本地当前最大值的记录；
- **云端为准**：字典/统计表以云端数据为基准整表合并，本地缺失则补齐。

### 4.2 两类同步方式

| 表类型 | 判定依据 | 同步方式 |
|--------|---------|---------|
| 自增主键表（日志/大表） | `extra` 含 `auto_increment` | 增量：`WHERE 主键 > 本地max` 导出，`INSERT IGNORE` 导入 |
| 非自增主键表（字典/统计表） | 主键非自增 | 整表 `INSERT IGNORE` 合并 |

### 4.3 主键增量原理

以 `co_block` 为例：
- 本地当前 `MAX(rowid) = 50,418,966`
- 云端当前 `MAX(rowid) = 52,878,507`
- 本次增量范围：`WHERE rowid > 50418966`
- 云端删除旧 rowid 不影响本地已同步的历史数据

由于自增主键单调递增，云端新数据的主键必然大于本地已同步值，因此增量判断可靠且不会重复/遗漏。

## 7. 脚本执行流程（sync_mysql.ps1）

```
1. 加载配置（4 个库）
2. 测试云端、本地连接（失败则退出）
3. 遍历每个数据库：
   a. 读取云端表清单
   b. 获取各表主键列及是否自增
   c. 读取云端主键最大值、本地主键最大值
   d. 若本地缺表，先用 mysqldump --no-data 建结构
   e. 按表类型选择增量或整表导出（mysqldump --result-file）
   f. 用 cmd /c 重定向导入本地（INSERT IGNORE）
   g. 导入后核验本地主键最大值，写入日志
4. 汇总本次新增行数，写入日志
```

### 关键技术点

| 要点 | 实现方式 |
|------|---------|
| 二进制安全导出 | `mysqldump --result-file`（避免 PowerShell 重定向损坏 blob） |
| 幂等导入 | `INSERT IGNORE`（主键冲突自动跳过） |
| 增量条件 | `--where="主键 > 本地max"` |
| 避免建表 DDL 冲突 | `--no-create-info --skip-add-drop-table`（仅导数据） |
| 大文件导入 | 通过 `cmd /c` 使用 `<` 重定向（PowerShell 不支持） |

## 11. 安全注意事项

1. **密码保护**：`sync_config.ps1` 明文存储数据库凭据，务必限制文件权限，禁止外传；
2. **网络访问**：同步依赖云端 123.207.3.73:3306 对外可达，注意云端安全组/防火墙放行；
3. **备份复核**：建议定期（如每月）将本地 `coreprotect`、`postracker`、`host21k5c4`、`plan` 另做一份离线冷备，防止本地磁盘故障导致历史数据丢失；
4. **磁盘空间**：本地数据库将持续增长（保留全部历史），需监控磁盘容量，规划扩容或归档策略；
5. **最小权限**：建议云端为同步账号单独创建只读权限账号（本系统当前使用全库权限账号，可按需收紧）。

## 12. 常见故障排查

| 现象 | 可能原因 | 处理方法 |
|------|---------|---------|
| 导入报 `ASCII '\0' appeared` | PowerShell `>` 重定向损坏二进制 | 已改用 `--result-file`，勿回退为 `>` |
| 导入报 `Column count doesn't match` | 本地表结构与云端不一致 | 比对 `SHOW CREATE TABLE`，重建表结构 |
| 同步中断 / 本地落后 | 云端连接失败或脚本异常 | 查看 logs，检查网络与凭据，重跑脚本 |
| 计划任务未执行 | 权限/账号变更 | 用 `Get-ScheduledTask` 检查任务状态 |
| 大表导出超时 | co_block/co_entity 数据量大 | 同步脚本设 6 小时上限，建议避开高峰期（已设 04:30） |
