# Plan 服务器 / 玩家数据分析工具 · 使用文档

本目录用于 **把 Minecraft 服务器 Plan（Player Analytics）插件的 SQLite 数据库导出为 SQL 文本**，方便离线查看、备份与做数据分析。

> 数据来源：`F:\game\pc\MC\开服\服务器数据备份\leaf-1.21.11\plugins\Plan\database.db`
> 该库为 **明文 SQLite**（说明服务端配置的是 SQLite 存储，而非默认 H2），可直接导出、无需密钥。

## 二、db_to_sql.py 使用说明

### 环境要求
- 任意装了 Python 3 的环境（脚本仅用标准库 `sqlite3`，**无需 `pip install`**）。

### 命令
```bash
# 基本用法：输出同名 .sql 到源文件同目录
python db_to_sql.py "路径/xxx.db"

# 指定输出文件
python db_to_sql.py "路径/xxx.db" "输出/out.sql"
```

### 工作原理
- 用 `sqlite3.connect()` 打开库，调用 `conn.iterdump()` 生成标准 SQL：
  - 先 `PRAGMA foreign_keys=OFF;` + `BEGIN TRANSACTION;`
  - 每张表一条 `CREATE TABLE`
  - 每行一条 `INSERT INTO ... VALUES(...)`
  - 结尾 `COMMIT;`
- 文本以 UTF-8 写入，中文字段不丢。

### 错误与处理
- **找不到文件** → 检查路径/文件名（中文路径需用英文引号包住）。
- **`无法以明文 SQLite 打开`** → 该库是 SQLCipher 加密库（如微信 `xwechat_files`）或损坏/非 SQLite 文件，本脚本无法处理，需先用密钥解密。

## 三、Plan_database.sql 内容说明

转储包含 Plan 插件全部表。常用表按用途分类：

### 玩家与账号
| 表 | 内容 |
|----|------|
| `plan_users` | 玩家主表：uuid、注册时间、名称、被踢次数 |
| `plan_user_info` | 每服务器维度：加入地址、是否 OP、是否封禁 |
| `plan_nicknames` | 历史昵称 |
| `plan_geolocations` | 地理位置/IP 归属（含隐私） |
| `plan_platforms` | 基岩/Java 跨端绑定信息 |

### 行为与时长
| 表 | 内容 |
|----|------|
| `plan_sessions` | 每次在线会话：起止时间、击杀、死亡、挂机时长 |
| `plan_kills` | 击杀记录：杀手/受害者 uuid、武器、时间 |
| `plan_ping` | 延迟数据（max/min/avg） |
| `plan_tps` | 服务器 TPS、在线人数、CPU/内存/实体/区块/磁盘 |

### 服务器与扩展
| 表 | 内容 |
|----|------|
| `plan_servers` | 服务器列表（uuid、名称、是否代理、Plan 版本） |
| `plan_worlds` | 世界列表 |
| `plan_plugin_versions` | 各服务器插件版本 |
| `plan_access_log` | Plan Web 面板访问日志（含访问者 IP、请求路径） |
| `plan_extension_*` | 扩展插件注入的自定义数据（providers / tabs / values 等） |
| `plan_security` / `plan_web_*` | Plan Web 后台账号、权限组、偏好 |

## 四、如何导入 / 分析

### 方式 A：命令行 sqlite3
```bash
# 把 .sql 重新导入一个新库
sqlite3 new.db < Plan_database.sql

# 直接查询示例：查看玩家注册列表
sqlite3 Plan_database.sql "SELECT uuid,name,registered FROM plan_users LIMIT 10;"
```

### 方式 B：Navicat / DBeaver
1. 新建 SQLite 连接 → 导入 `Plan_database.sql`（或先建空库再「运行 SQL 文件」）。
2. 用图形界面浏览表、写查询。

### 方式 C：导入 MariaDB / MySQL（重点）
> ⚠️ **SQLite 的 `.sql` 不能直接 source 进 MariaDB**，会报 `1064 - near 'PRAGMA foreign_keys=OFF'` 语法错误——SQLite 的 `PRAGMA`、双引号标识符、类型写法 MariaDB 都不认。请改用 `Plan_database.mariadb.sql`（已按 MySQL 方言生成）。

1. 在 MariaDB 里先建好目标库：
   ```sql
   CREATE DATABASE plan_db CHARACTER SET utf8mb4;
   USE plan_db;
   ```
2. 导入 MariaDB 方言文件（大文件建议用命令行，比图形界面稳）：
   ```bash
   mysql -u 用户名 -p plan_db < Plan_database.mariadb.sql
   ```
   或在 Navicat 里「运行 SQL 文件」选择 `Plan_database.mariadb.sql`。
3. 该文件已处理：反引号标识符、`INT AUTO_INCREMENT PRIMARY KEY`、类型映射（bigint→BIGINT、boolean→TINYINT、text→TEXT）、`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`，末尾 `SET FOREIGN_KEY_CHECKS=1;`。
4. 重新导出：线上库更新后跑 `python db_to_mariadb.py 数据库.db Plan_database.mariadb.sql` 即可。

### 常用分析查询示例
```sql
-- 总在线时长 Top10 玩家（秒）
SELECT u.name, SUM(s.session_end - s.session_start)/1000 AS online_sec
FROM plan_sessions s
JOIN plan_users u ON u.id = s.user_id
GROUP BY u.id ORDER BY online_sec DESC LIMIT 10;

-- 击杀榜
SELECT killer.name AS killer, COUNT(*) AS kills
FROM plan_kills k
JOIN plan_users killer ON killer.uuid = k.killer_uuid
GROUP BY killer.uuid ORDER BY kills DESC LIMIT 10;

-- 服务器平均 TPS（低于 20 说明有卡顿）
SELECT name, AVG(tps) FROM plan_tps t
JOIN plan_servers s ON s.id = t.server_id GROUP BY s.id;
```

> 时间字段为 **Unix 毫秒**（bigint），做展示时需 `/1000` 转秒再格式化。

## 五、注意事项

1. **隐私风险**：`Plan_database.sql` 含玩家 **UUID、IP、地理位置、行为日志** 等敏感数据，纯文本存放，**不要随意外传或提交到公开仓库**。
2. **只读用途**：本转储用于分析/备份，请勿直接回写覆盖线上 `database.db`，避免破坏 Plan 运行中的库。
3. **重新导出**：线上库更新后，重新跑 `db_to_sql.py` 即可生成最新 `.sql`（建议加日期命名，如 `Plan_database_2026-09-26.sql`）。
4. **加密库不适用**：若后续要转微信等加密 `.db`，需先解密，本脚本不支持。
5. **方言别混用**：`Plan_database.sql` 只给 **SQLite** 客户端用；要进 **MariaDB/MySQL** 必须用 `Plan_database.mariadb.sql`，否则报 1064 语法错误。
