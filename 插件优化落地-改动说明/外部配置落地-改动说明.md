### 4.1.1 参数含义

这些是 **JVM（Java 虚拟机）启动参数**，控制跑服务端那个 Java 进程的内存分配与垃圾回收，直接影响卡顿与 TPS 稳定性（非服务器设置）。

**① 堆内存 `-Xmx6G -Xms6G`**
- `-Xmx6G` 堆内存上限 6GB；`-Xms6G` 初始即 6GB。
- 两者相等 → 启动即定到 6G，运行中**不再同步扩容/收缩**（扩容会卡）。原值 `Xmx4G Xms1G` 运行时要从小往大扩，有隐性卡顿。

**② 20 个 Aikar G1GC 参数**（Aikar 为 MC 工作负载特调，来自 `mcflags.emc.gs`）

| 分组 | 参数 | 作用 |
|---|---|---|
| 选回收器 | `-XX:+UseG1GC` | 用 G1 回收器（适合大堆、可预测停顿，MC 首选） |
| 停顿目标 | `-XX:MaxGCPauseMillis=200` | 每次 GC 停顿尽量 ≤200ms，避免明显卡顿 |
| 后台并行 | `-XX:+ParallelRefProcEnabled` | 引用处理并行，少占主线程 |
| 禁强退 | `-XX:+DisableExplicitGC` | 禁止代码 `System.gc()` 强制全停顿回收 |
| 内存预占 | `-XX:+AlwaysPreTouch` | 启动时把 6G 页提前触碰到位，运行期不再边用边分配 |
| 新生代比例 | `G1NewSizePercent=30` `G1MaxNewSizePercent=40` `SurvivorRatio=32` `MaxTenuringThreshold=1` | 给新建对象区足够空间，让短命对象快速回收 |
| 老年代节奏 | `InitiatingHeapOccupancyPercent=15` `G1MixedGCLiveThresholdPercent=90` `G1MixedGCCountTarget=4` `G1HeapWastePercent=5` | 提前且平稳混代回收，避免一次性大停顿 |
| 预留应急区 | `G1ReservePercent=20` | 留 20% 堆给紧急分配，防止耗尽触发强制全回收 |
| 分区/RSet | `G1HeapRegionSize=8M` `G1RSetUpdatingPauseTimePercent=5` | 调分区与记忆集更新，降低停顿开销 |
| 解锁实验项 | `-XX:+UnlockExperimentalVMOptions` | 允许上述部分 G1 实验参数生效 |
| 标记（无害） | `-Dusing.aikars.flags=...` `-Daikars.new.flags=true` | 仅来源标记，无功能影响 |

一句话：在 6G 堆内用 G1 回收器、按 MC 的工作量特调，目标是**回收垃圾时停顿更短更平顺**，少掉 TPS、少卡顿，对后期内存大了以后 GC 频繁卡顿最有效。

### 4.3 两个参数的含义

这两个都是**原版/Paper 服务端 `server.properties` 参数**（非插件设置），本次改动是纯性能优化，零功能损失。

**① `sync-chunk-writes=false` —— 区块保存是否同步写盘（治"自动存档卡顿"）**

| 值 | 行为 | 效果 |
|---|---|---|
| `true`（原值） | 自动存档时，主线程**干等磁盘写完**才继续 | 每次自动存档都会卡顿/掉 TPS（磁盘慢、实体多时尤其明显） |
| `false`（改后） | 区块存盘放到**后台异步**执行，主线程不等待 | 存档时不卡，TPS 稳 |

取舍：`false` 下若服务器瞬间断电/崩溃，可能有极少量刚生成区块未落盘丢失；但 Paper/Leaf 每 5 分钟自动存档，配合正常关服存档日常无感，官方主流建议即 `false`。

**② `network-compression-threshold=256` —— 网络压缩阈值（治"压缩吃 CPU"）**

数据包字节数**达到该值**才做 zlib 压缩（减小体积省带宽），低于该值不压（省 CPU）。

| 值 | 行为 | 效果 |
|---|---|---|
| `64`（原值） | 几乎**所有包都压缩** | CPU 大量时间压小包——小包不占带宽，压了收益极小，纯浪费 |
| `256`（改后） | 只压缩 ≥256 字节的较大包 | 大幅降低压缩 CPU 开销，带宽几乎不受影响 |
