## 1. 玩法速览

打开自己的背包，**右键点击背包里的潜影盒**，直接弹出 27 格潜影盒界面，不用把盒子放到地上再挖掉。存完东西关掉界面，内容自动写回背包里那个盒子，可以继续带着走。

- 支持普通潜影盒 + 全部 16 种染色潜影盒（`Material.name().endsWith("SHULKER_BOX")`）。
- 只处理**玩家自己背包**里的点击；箱子、末影箱界面里的潜影盒不触发。
- 原版的放置、挖掘、漏斗/发射器搬运、潜影盒 NBT 全部不受影响。
- 纯服务端，玩家不用装任何客户端 mod；插件零配置、零命令、零权限。

## 2. 触发条件（1.3.0 反编译实测）

`ShulkerListener` 只注册 `InventoryClickEvent` / `InventoryDragEvent` / `InventoryCloseEvent` 三个事件，**没有** `PlayerInteractEvent`，所以「手持潜影盒对空气右键」不会打开。

| 检查                       | 判定                                                              | 不满足时                       |
| -------------------------- | ----------------------------------------------------------------- | ------------------------------ |
| 点击者                     | `getWhoClicked() instanceof Player`                               | 忽略                           |
| 点击的容器                 | `getClickedInventory() == player.getInventory()`                  | 忽略（别的容器里不算）         |
| 被点的物品                 | 名字以 `SHULKER_BOX` 结尾                                        | 忽略                           |
| 是否数字键换栏             | `getHotbarButton() == -1`                                        | 直接返回，不打开               |
| 是否 Shift 点击            | `!isShiftClick()`                                                 | 取消事件并返回                 |
| 是否右键                   | `isRightClick()`                                                  | 左键走原版，不打开             |
| 打开动作                   | `setCancelled(true)` → `clone()` 物品 → 记录原槽位 → 下一 tick 打开 | —                              |

打开时：`createInventory(holder, 27, "Shulker Box")`，从 `BlockStateMeta → ShulkerBox.getInventory()` 复制内容。关闭时先校验原槽位仍是潜影盒再写回，不是就直接丢弃（防复制）。界面打开期间拖拽与数字键换栏一律取消 —— 这是 1.1.0 起加的防复制保护，1.2.0 修了「界面意外关闭」的边界问题。

## 3. 命令 / 权限 / 配置

| 项         | 结论                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| 玩家命令   | **无**，纯交互                                                                                                         |
| 管理员命令 | **无**，没有 reload 命令；任何变更都要完整重启服务端                                                                     |
| 权限节点   | `plugin.yml` 未声明权限节点，**所有玩家默认可用**；无需 LuckPerms 授权，也**无法按组关掉**（只能不装或用别的插件拦事件） |
| 配置文件   | 无 `config.yml`、无数据目录；物品内容存在潜影盒物品自身 NBT 里                                                           |

> 这条和本服其它玩法插件不同：本服是 LuckPerms 显式授权模式，绝大多数功能要 `/lp group ... permission set`；OpenShulk 不需要，也做不到分组开关。

## 4. 本服已知限制（比功能更重要）

### 4.1 基岩端右键大概率不生效

本服玩家以基岩端为主，经 Geyser 接入。**Geyser 无法区分背包 GUI 内的左键 / 右键**，而本插件唯一入口就是 `InventoryClickEvent.isRightClick()` —— 基岩玩家在背包里点潜影盒可能被映射成左键，界面打不开。

- 本服 BedrockPlayerSupport 2.1.1 只提供 warp / kit / tp / msg / back 等表单，**没有潜影盒相关能力**，也没有命令/表单兜底。
- 基岩玩家打不开时，仍走原版流程：把潜影盒放到地上 → 打开 → 存取 → 挖回。
- 该结论是 Geyser 层的通用限制，换同类插件（只要依赖背包内右键）一样存在；选型时优先考虑「手持右键空气」类实现，或另写表单/命令兜底。

### 4.2 CoreProtect 审计盲区

CoreProtect 的 `co_container` 只记录**世界中已放置的容器**。OpenShulk 走自定义 `InventoryHolder` 的虚拟 Inventory，物品不落地，因此**背包内直开潜影盒的存取不会进 `co_container`**，物品纠纷无法用 `/co inspect` / `/co lookup` 追溯。

若后续需要审计，得另做记录（自研插件监听 `InventoryClickEvent` 写流水），不能指望 CoreProtect。

### 4.3 其它

- 插件只认标准潜影盒；模组/自定义容器类物品不保证兼容（官方声明）。
- 关闭界面时若原槽位已不是潜影盒（被换栏、被拿走），本次改动**直接丢弃**，这是防复制的代价，别误以为丢物品是 bug。
- 与同类「打开潜影盒」插件**不要同时装**，会抢同一个 `InventoryClickEvent`。

## 5. 部署 / 升级 / 回滚

| 步骤 | 操作                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------- |
| 部署 | 把 `openshulk-26.x.jar` 放进 `plugins/`，**停服完整重启**（不要用 `/reload`）                          |
| 校验 | `sha1sum openshulk-26.x.jar` → `0efd86a4d510dac726f40611c61d850d082f79ee`；`/plugins` 看到 `OpenShulk`；进背包右键潜影盒能开界面 |
| 升级 | 停服 → 旧 jar 改名 `.bak-YYYYMMDD`（不删）→ 放新 jar → 完整重启                                        |
| 回滚 | 停服移走 jar → 完整重启。无配置、无数据目录，不会留下残留                                               |

## 7. 排错

| 现象                         | 原因 / 处理                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| 右键没反应（Java 端）        | 确认点的是**自己背包**里的盒子；Shift、左键、数字键换栏都不触发；确认不是放在箱子里点的       |
| 右键没反应（基岩端）        | Geyser 右键限制，见 §4.1；改原版放置后打开                                                    |
| 手持盒子对空气右键没反应     | 设计如此，1.3.0 没有 `PlayerInteractEvent`                                                     |
| 存进去的东西没保存           | 界面开着时把盒子移走/换栏了，关闭时槽位校验失败会丢弃改动                                     |
| 界面打开时拖不动、换不了栏   | 1.1.0 起的防复制保护，故意取消，不是 bug                                                       |
| `/plugins` 里版本号看着不对  | 发布号 1.3.0，jar 内 `plugin.yml` 写 1.2.0，属版本漂移；以 sha1 核对文件                      |
| 服务端起不来 / 类版本报错    | 该 jar 是 Java 25 字节码（major 69），服务端必须是 Java 25；本服实跑 Java 25，满足条件       |
