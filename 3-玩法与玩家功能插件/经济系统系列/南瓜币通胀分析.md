# 南瓜币通胀分析（进出水口全貌与治本方案）

> 结论先行：**每日封顶只治「急性通胀」，治不了「慢性通胀」。**封顶限制的是单人单日的注水速度，不是货币总量。只要进水口（faucet）长期大于出水口（sink），货币存量就会持续上涨——哪怕每个玩家每天都只卖一点点。真正决定物价的是 **净注水 = faucet − 实际回收的 sink**，治本要动出水口和存量，不是继续拧水龙头。
>
> 本文只做分析与方案对比，**不含任何已执行的配置改动**。数值来源：[南瓜币获取方式.md](南瓜币获取方式.md)（进水侧）、[服务器扣费点清单.md](服务器扣费点清单.md) 与 [经济插件/EzTax周持有税.md](经济插件/EzTax周持有税.md)（出水侧），均为仓库既定配置核对口径。

## 1. 净注水模型

```
货币存量变化 = 进水口(faucet) − 出水口(real sink)

faucet：任务 / 收购 / 在线 / 离线 / 工具包 / 钓鱼 / 活动邮件 —— 凭空新增南瓜币
sink  ：税费 / 上架费 / 商店创建费 / 手续费 —— 只有「真正销毁或沉淀出流通」才算回收
```

- **封顶的意义**：把 faucet 的**峰值速率**压下来，防的是「小号挂机一夜刷爆」这种急性通胀。FishLimit 300/天、DailySell 900/天、在线 300/天都属于这一层。
- **封顶的盲区**：一个玩家每天只拿一点点、但天天上线，一年照样注入数万到数十万币。速率低 ≠ 总量不涨。
- **关键判据**：sink 必须「无论玩家消不消费都能回收」，否则钱被攒着不花时，出水口等于零。

### 现行 sink 的三个真问题

1. **财富税门槛形同虚设**：起征 25 万。按上面算账，全勤玩家一年攒 64 万，只有超出的 39 万被征 2% ≈ 7800 币——相对 64 万注水量杯水车薪，普通玩家更是完全无感。
2. **大多数 sink 要「花钱」才触发**：交易税、商店税、拍卖税都挂在消费行为上。玩家一旦选择攒钱不花，这些出水口几乎全关。
3. **税款去向可能不是真销毁**：`EzTax` 当前 `tax-sink.destination: player`，税款转入 `PumpkinVegetable` 账户，属**账户间转移**，不是 `burn`（销毁）。只要这笔钱再流回市场（该账户消费、发奖励等），所谓的「收税」就没真正减少流通量。要做严格 Sink，应改 `destination: burn`。

> 口径提示：扣费清单里写过「税收进国库销毁」，但 EzTax 分册（较新，2026-11-14 核对）的实跑配置是 `player` 转账户。以分册的当前值为准，改 `destination` 前先看 `/tax sinks` 实测确认。

## 4. 为什么「每天卖一点」还是会泛滥（算账）

设某玩家每天只从钓鱼拿 50 币（远低于 300 封顶），一年 = 50 × 365 ≈ **1.8 万币**。
这部分钱若从不消费（不交易、不上架、不开店），现行 sink 对它**一分钱都收不到**——因为财富税门槛 25 万没到，交易类税又没触发。
结论：**封顶数值再低，只要钱只进不出、且没有被动回收，长期就是净注水。**这正是你说的「不卖鱼一天卖一点也还是泛滥」。

## 5. 治本方案对比

| 方案                    | 怎么改                                                             | 对「攒钱不花」有效    | 代价 / 注意                                              |
| ----------------------- | ------------------------------------------------------------------ | --------------------- | -------------------------------------------------------- |
| **A. 降财富税门槛**     | `wealth-tax.threshold` 25 万 → 2~5 万，可配 `brackets` 累进        | ✅ 有效，被动征收     | 中高余额玩家被回收，需公告；门槛值服主定                 |
| **B. 税款改 burn**      | `tax-sink.destination: player` → `burn`                            | ✅ 让已收的税真正销毁 | 转账户模式改为销毁，收款账户 `PumpkinVegetable` 不再进账 |
| **C. 开命令收费**       | Essentials `command-costs` 给 `/home` `/tpr` `/warp` `/spawn` 定价 | ⚠️ 半有效，看使用频率 | 日常高频操作稳定 burn 币，玩家成本略升                   |
| **D. 提高流通税**       | 拍卖成交税、玩家商店交易税 5% → 上调                               | ❌ 对攒钱无效         | 压制玩家间交易，慎重                                     |
| **E. 加金币 burn 玩法** | 小游戏入场费 / 装扮商城 / 每日服务费                               | ✅ 有效，给钱消费出口 | 需配置或开发新功能                                       |

**推荐优先级**：A（降门槛）→ B（改 burn）→ C（命令收费）→ E（burn 玩法）。
A + B 是「普通玩家攒着也会被回收 + 税收真正销毁」的组合，直接堵住第 4 节的漏洞；两者都只改 EzTax 配置、不动代码。C 作为补充出口。D 对「攒钱不花」无效，优先级最低。

> faucet 侧不必再加码：钓鱼封顶后仅占全勤收入约 17%，继续压它的边际收益很低。若仍想收紧，DailySell 900/天才是最大的单一 faucet，但那属「干活换币」的主动收入，压它要权衡玩家体验。

## 6. 落地边界

- 本文为分析文档，所有数字为既定配置核对值，**未改动任何插件配置**。
- 真要落地 A/B/C，需由服主定具体数值（门槛、税率、命令定价），改完按各插件要求 `/tax reload` 或重启生效；本方案不启服、不 reload、不碰运行数据库与云端。
- 调参后建议用 `/tax stats`（Total removed）、南瓜账本 MoneyLedger 流水、全服余额分布三方对照，观察 1~2 周净注水是否收敛。
