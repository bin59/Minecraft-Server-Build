## 三、正确的导入方式（按文件形态选，别再一律丢 `imports/`）

FMM 2.14+ 的 `imports/` **只可靠处理单个 `.bbmodel`**：不收散放的同名 `.yml`/`.json`/`.png`，也不递归导入没有 `pack.meta` 的普通子文件夹（官方 wiki「手动模型导入」「模型创作注意事项」）。

| 拿到的东西 | 放到哪 | 命令 |
|---|---|---|
| 单个 `.bbmodel` | `plugins/FreeMinecraftModels/imports/` | `/fmm reload`（转成 `.fmmodel` 写入 `models/`，源文件会留在 imports，之后 reload 会重复转换） |
| `.bbmodel` + 同名 `.yml` / 展示 `.json` / 纹理 `.png` | **直接放 `plugins/FreeMinecraftModels/models/<包名>/`**（该目录递归读取） | `/fmm reload` |
| 带脚本/附魔的完整包 | 解压后把 `models/`、`scripts/`、`enchantments/` 分别并入插件同名目录 | `/fmm reload`，`config.yml`/`shop_config.yml` 不会被重读 |
| 规范内容包 zip（有 `pack.meta`，如官方包） | `imports/` 整包不解压 | `/fmm reload` 或 `/fmm setup` 安装 |

配套 `.yml` 示例（放在模型旁，文件名与模型一致，小写）：

```yaml
isEnabled: true
material: PAPER
name: "&6南瓜灯"
lore:
  - "&7图书馆展区装饰"
scripts: []
```

自定义物品要在 `.yml` 里写 `material:`，用 `/fmm giveitem <id>` 取；装饰物要做配方才进 `/fmm` 菜单（`/fmm craftify <id>` 或开 `shop_config.yml`）。

## 四、避坑

1. **ID 规范化冲突**：文件名会转小写、非 `a-z0-9._-` 字符替换为 `_`。同名不同内容的模型会**全部被拒绝加载**，控制台报 `Rejected normalized model ID collision`。命名一律小写下划线。
2. **ItemsAdder / Nexo / Oraxen 专属包不兼容**；MCModels 免费包多数属此类，别下。
3. **基岩端**：模型至少要有一张纹理才会被导出到基岩包；`/fmm reload` 后 Geyser 的 mappings 只在启动读取，**改完模型要重启一次**才对基岩生效。
4. **装完资源包会重新生成** → §4.5 的两个分发包立刻过期，玩家要重新下载安装；本服 RPM 会自动合并并推送。
5. **备份**：动 `models/` 前先备份整个 `plugins/FreeMinecraftModels/`；`/fmm reload` 验证失败时旧目录仍有效，别假设已经生效，看控制台与 `/fmm admin`、`/fmm stats`。
6. 本服 FMM **2.14.2**，官方最新 2.15.0（启动日志已提示）；升级后才会多出 3 个宠物包清单，但宠物包仍未发布，拿不到内容。
