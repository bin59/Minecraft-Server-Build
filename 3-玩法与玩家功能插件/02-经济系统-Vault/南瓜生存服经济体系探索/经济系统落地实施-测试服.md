## 0. 落地前现状核查（重要结论）

**结论：本服经济已经是"单账本"，不存在双经济。**

- 测试服 `plugins/Vault.jar` 为 **Vault 1.7.3-b131（Roydogman 桥版）**，`main: net.milkbowl.vault.Vault`，是标准 Vault API 桥。
- 启动日志实证（`logs/latest.log`）：
  ```
  [Vault] [Economy] Essentials Economy found: Waiting
  [Vault] [Economy] Essentials Economy hooked.
  [Essentials] Using Vault based permissions (LuckPerms)
  [DeluxeMenus] Successfully hooked into Vault!
  [CustomDeathMessages] Initializing VaultManager...
  ```
  → **全服经济账本统一在 EssentialsX**，Residence / CustomDeathMessages / SimplePets / DeluxeMenus / PlaceholderAPI 全部走 Vault API 读同一本账。
- ⚠️ **历史误导**：`plugins/Vault/` 下曾残留一份 "Vault 2.0 internal economy" 格式的 `config.yml / balances.yml / loans.yml`（配置格式与桥版 jar 不匹配，桥版不读取）。2026-09-16 校准报告据此误判"双经济并存"。**已于 2026-09-17 移入 `plugins/Vault/_vault2-backup-20260917/` 备份**，排除混淆。

**因此落地无需换 Vault jar、无需余额迁移**，只需配置 EssentialsX 及相关插件。

## 4. 经济健康监控（每周跑一次）

**核心公式**（手册 §3.6）：`周 Faucet（系统发放）≤ 周 Sink（系统回收）`

| 项 | 怎么查 | 判定 |
|---|---|---|
| 周 Faucet | `/eco` 发放记录 + Plan 活动数据 | 合计记入表 |
| 周 Sink | 传送/领地/死亡/拍卖税记录 | 合计记入表 |
| 货币净增量 | `Faucet − Sink` | **> 0 且持续 → 预警，调参** |
| 系统发放占比 | Faucet ÷ 玩家总收入 | 理想 < 50%（大头来自市场交易） |

**调参杠杆**（手册 §3.6C）：
- 印钱（Faucet > Sink）：降任务额度；提上架费/税率/领地单价
- 偏紧（Sink ≫ Faucet）：适度提发放或降部分 Sink
