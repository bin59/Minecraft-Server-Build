# 自定义模型物品：能不能做、怎么做

> 适用：Leaf 1.21.11 双端互通服（Java + 基岩），本目录已备好**可运行的资源包骨架**。
> 状态：**能做**。纯资源包路线零插件、零依赖，本目录的 zip 已经可以直接下发。

---

## 一、一句话结论

**能做出"跟原版长得完全不一样的物品"，但有个绕不过去的边界：资源包只改客户端显示，不能改物品本身。** 也就是说你只能让" existing 的原版物品"穿上新外衣，**变不出一个官方不存在的新物品 ID**。要新 ID + 特殊逻辑，才需要插件。

---

## 二、能做什么 / 不能做什么

| 想做的事 | 资源包 | 插件 | 说明 |
|---|---|---|---|
| 换 2D 贴图（钻石剑 → 南瓜刃外观） | ✅ | 不需要 | 放 `textures/item/*.png` 覆盖同名文件 |
| 做 3D 立体模型（自己的形状、厚度） | ✅ | 不需要 | 在模型 json 里写 `elements` |
| 一个物品多个外观（按数据切换） | ✅ | 不需要 | `custom_model_data` 分层 |
| 中文名 / Lore / 自定义附魔 | ✅(显示) | 不需要 | 中文名靠资源包 `lang`，附魔靠命令 |
| **凭空造一个新物品 ID**（如"南瓜手机"） | ❌ | ✅ | 服务端不认自定义 ID，必须 ItemsAdder / Oraxen 这类插件注册 |
| 物品特殊行为（右键放烟花、掉落的特殊效果） | ❌ | ✅ | 资源包管不到逻辑 |
| 基岩端也看到自定义模型 | ❌ | ⚠️ | 见 §五，**这是本服最大的坑** |

> 资源包优先级高于原版资源：把 `models/item/diamond_sword.json` 放进资源包，就能整体覆盖原版那个模型。

## 三、四条路线对比

| 路线 | 装什么 | 难度 | 玩家要不要装东西 | 适合 |
|---|---|---|---|---|
| **A. 纯资源包 + 命令** | 什么都不用装 | ⭐ 最低 | 服务端下发则不用 | 换外观、做主题服装/武器皮肤 |
| **B. A + 服务端自动下发** | 同上，多配 `server.properties` | ⭐⭐ | 不用（首次进服下载） | 上面 Same，且不想让玩家手动装 |
| **C. ItemsAdder** | `ItemsAdder.jar` | ⭐⭐⭐ | 仍走资源包 | 要有**全新物品 ID**、单个物品的属性/配方/附着效果 |
| **D. Oraxen / Nexo** | 对应 jar | ⭐⭐⭐ | 同上 | 同上，偏 aurora 风格 |

**推荐**：先走 **A/B**。本目录的 zip 就是 A/B 的完整实现，先跑通再决定要不要上 C。

### C（ItemsAdder）的两个本服加分项

- 支持从 **Litematica 的 `.schematic` 直接导入成 3D 模型**（`.iaModel`），你本来就在用 Litematica，工具链现成。
- 自带自定义物品属性、配方、附魔，不用再写命令。
- ⚠️ Geyser 兼容性**官方没有完整声明**，基岩端显示要实测。

## 四、本目录资源包：结构与用法

```
09-自定义模型物品/
├─ 模型物品资源包/            ← 资源包源文件（可直接编辑）
│  ├─ pack.mcmeta             ← 版本号与描述
│  ├─ pack.png                ← 资源包图标 64x64
│  └─ assets/minecraft/
│     ├─ lang/zh_cn.json      ← 中文名："南瓜刃"、"虚空核"
│     ├─ models/item/
│     │  ├─ diamond_sword.json ← 覆盖原版钻石剑：换贴图 + 两种外观切换
│     │  ├─ pumpkin_blade.json ← 南瓜刃（2D 贴图，parent: item/generated）
│     │  └─ nexus_core.json    ← 虚空核（3D 立方体，parent: item/flat + elements）
│     └─ textures/item/
│        ├─ pumpkin_blade.png  ← 占位图（橙黄渐变，替换成真图即可）
│        └─ nexus_core.png     ← 占位图（紫色渐变）
├─ 自定义模型物品包.zip        ← 已打包好的资源包，直接下发
├─ 打包资源包.bat              ← 改完源文件后双击重新打包
├─ 打包资源包.py
└─ 生成纹理.py                 ← 生成占位 PNG，画好真图后可删
```

### 部署步骤

**第 1 步：改美术（可选）**
把 `textures/item/*.png` 换成你画的真图（建议 32x32 或 64x64，PNG 带透明通道）。文件名别改，模型里引用的是文件名。

**第 2 步：重新打包**
双击 `打包资源包.bat`（需要 Python 3）。输出 `自定义模型物品包.zip`，脚本会顺带打印 **SHA1**。

> 必须保证 zip **根目录下直接就是 `pack.mcmeta` 和 `assets/`**，不能多套一层文件夹。

**第 3 步：托管到 HTTPS**
把 zip 丢到 Caddy/静态站点目录，得到 `https://你的域名/pumpkin-models.zip`。外网必须是 HTTPS。

**第 4 步：写 server.properties**
```properties
resource-pack=https://你的域名/pumpkin-models.zip
resource-pack-sha1=第2步打印的40位哈希
require-resource-pack=false
resource-pack-prompt={"text":"下载南瓜模型包以显示自定义物品外观","color":"gold"}
```
改完**重启服务端**。

> `require-resource-pack=false`：不强制，拒绝的玩家照样能玩，只是看到的还是原版外观。
> 设成 `true` 会直接踢掉拒绝下载的玩家，**不建议**。

**第 5 步：测试**
游戏内（OP 执行）：
```
/item give @s diamond_sword[minecraft:custom_model_data={tags:["101"]}]
/item give @s diamond_sword[minecraft:custom_model_data={tags:["102"]}]
```
- tags `101` → 南瓜刃贴图
- tags `102` → 虚空核（3D 方块）

> ⚠️ **别用 `/give ... {CustomModelData:101}`** —— 1.21.2 起 `/give` 不再接受 NBT 标签，只能用 `/item give` 加方括号组件语法。

名字和 Lore 也可以直接给：
```
/item modify entity @s weapon.item_name set "{\"text\":\"南瓜刃\",\"color\":\"gold\"}"
/item modify entity @s weapon.lore append "{\"text\":\"切蔬菜专用\",\"color\":\"gray\"}"
```

## 五、基岩端限制（重要）

**Bedrock 客户端不读 Java 版服务端的 `resource-pack` 配置。** Geyser 也只是在协议层做翻译，不会替你下载资源包。所以：

| 端 | 能看到自定义模型吗 |
|---|---|
| Java 版客户端 | ✅ 资源包下发后自动生效 |
| 基岩版客户端 | ❌ 看不到，仍是原版外观 |

**想让基岩端也看到，只有两条路：**
1. 让基岩玩家**自己**在资源包设置里手动添加这个包（Geyser 的 Bedrock 资源包支持有限，需实测）
2. 上 ItemsAdder/Oraxen 这类插件 + 用世界模板（world template）把资源包塞进基岩端能读的位置

> 顺带一提：你之前遇到的"皮肤头全是史蒂夫"就是同一类问题——客户端有没有拿到对应的资源/数据。

## 六、排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 物品没变化 | `/give` 的 NBT 写法在 1.21+ 已失效 | 改用 `/item give ...[组件]` |
| 客户端报"资源包版本不符" | `pack.mcmeta` 的 `pack_format` 不对 | 改成客户端提示的值（本包用的是 `supported_formats` 46~99 区间） |
| 资源包下载失败 | URL 非 HTTPS、SHA1 填错 | 重新算 SHA1，`Get-FileHash .\xx.zip -Algorithm SHA1` |
| 模型是黑的 / 缺面 | 纹理没配对，`layer3` 之类的层漏了 | 检查 `textures` 里引用的路径与实际 png 文件名一致 |
| 3D 模型显示位置奇怪 | 自定义 `elements` 必须自己写 `display` | 参考 `nexus_core.json` 的 display 段 |
| 基岩端没变化 | 见 §五 | 只能让玩家手动装 |
| 中文名没生效 | 语言文件键名或文件名不对 | 必须是 `assets/minecraft/lang/zh_cn.json`，键为 `item.minecraft.<物品id>` |
