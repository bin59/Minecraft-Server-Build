# 多服网络与端口架构

> 适用副本：`leaf-26.3-多服`（本地 `F:\game\pc\MC\开服\服务器数据备份\` 与云端两套独立维护，需手动同步）。运行时：Java 25（`jdk-25.0.5.0.3`）。
> 代理：**Velocity 4.3.1**；后端：**Leaf 26.3-18**（Paper 分支）。
> 认证：**YggdrasilOfficialProxy（YOP）2.3.0**，官方正版 + LittleSkin 外置登录混合，统一在代理层收口。
> **2026-11-18 起本多服已正式成为主服**（老主服关停），对外端口全部用回标准值：Java `55551`、基岩 `19132`、YOP survival `32217`。

## 2. 网络架构总览

```
                          互联网 / 玩家客户端
                                  │
         ┌────────────────────────┴────────────────────────┐
         │  对外入口（防火墙放行这两个，主服标准端口）        │
         │  Java : 0.0.0.0:55551  (TCP，公网直达 55551)     │
         │  基岩: 19132 (NetherNet，TCP+UDP 同号，公网直达)  │
         └────────────────────────┬────────────────────────┘
                                  │
                    ┌─────────────▼─────────────┐
                    │      Velocity 代理进程      │
                    │   velocity-4.3.1-45.jar    │
                    │   online-mode = true       │
                    │   forwarding = modern      │
                    │   本地认证 YOP :32218       │
                    │   Geyser-Velocity :19132    │
                    │   floodgate-velocity        │
                    └─────────────┬─────────────┘
              modern 转发（forwarding.secret 校验，只认代理）
        ┌──────────────┬──────────────┬──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
  survival        minigames       skyblock       lobby（预留，未启动）
  127.0.0.1:     127.0.0.1:     127.0.0.1:     127.0.0.1:
    30002          30003          30004          30001
  Leaf 26.3      Leaf 26.3      Leaf 26.3
  10G/4G 堆      3G/1G 堆       3G/1G 堆
  YOP :32217     YOP :32219     YOP :32220      —
  online=false   online=false   online=false
```

要点：代理是唯一入口，后端全在回环地址后面；认证与 UUID/皮肤解析在代理层（YOP）和转发阶段完成，后端只信任来自代理的连接。

| 19132 | TCP+UDP | 0.0.0.0 | 基岩玩家入口（Geyser-Velocity NetherNet，主服标准端口，TCP+UDP 同号） | 必放行 |

### 3.2 后端子服端口（只绑 127.0.0.1，禁止对外）

| 子服 | server-port | server-ip | online-mode | RCON | YOP 本地端口 | 堆内存 |
| --- | --- | --- | --- | --- | --- | --- |
| survival | 30002 | 127.0.0.1 | false | 25596 | 32217 | -Xmx10G -Xms4G |
| minigames | 30003 | 127.0.0.1 | false | 25596 | 32219 | -Xmx3G -Xms1G |
| skyblock | 30004 | 127.0.0.1 | false | 25596 | 32220 | -Xmx3G -Xms1G |
| lobby（预留） | 30001 | 127.0.0.1 | — | — | — | 暂不启动 |

> ⚠ **后端 `server-port` 永远不要改成对外端口**（如 55551 / 19132）。2026-11-18 曾把云端 survival 的 `server-port` 误改为 55551，与 Velocity 的 `bind = 0.0.0.0:55551` 撞车，后端启动即 `Failed to bind to port` / `Address already in use: bind` 崩溃。对外端口只属于代理层（Velocity 55551 / Geyser 19132）；后端固定 30002~30004 内部端口，改主服端口时**不要动它们**。排查此类崩溃先看崩溃报告所在目录确定是哪个服，再 `netstat -ano | findstr :<该服 server-port>` 查占用。
> RCON 已启用（`enable-rcon=true`，密码见各服 `server.properties`），仅回环可用。
> `management-server-enabled=false`，未启用新版管理端点。
> **RSPM 自托管 HTTP 端口**：ResourcePackManager 只装 survival，`selfHostPort: -1` 自动推导 = MC端口 + `networkHttpOffset-v2`。survival MC=30002，offset **必须 ≠ 1**（1 → HTTP 30003 会撞 minigames 的 MC 端口，报 `Address already in use: bind`）。当前 `networkHttpOffset-v2: 10` → HTTP **30012**（11-11 曾用显式 `selfHostPort: 30005` 修过，后配置回退复发；两种修法二选一勿并存）。改后重启 survival 生效，代理经 RSPM 自动公告拿端口。

### 3.3 认证 agent 本地端口（YOP，每 JVM 一份，必须互不相同）

| 实例 | YOP `server.port` | 说明 |
| --- | --- | --- |
| survival | 32217 | 后端子服专用（主服标准端口） |
| **Velocity** | **32218** | 代理端专用（认证收口） |
| minigames | 32219 | 后端子服专用 |
| skyblock | 32220 | 后端子服专用 |

> 四个 JVM 各带一份 YOP agent，`server.port` 必须互不相同，否则后启动的实例绑定失败并导致该服外置登录失效。
> 2026-11-18 老主服关停后，survival 从 32221 改回标准端口 **32217**；四端口 32217/32218/32219/32220 连续且互不冲突。

## 4. 关键配置基准

### 4.1 Velocity（`velocity/velocity.toml`）
- `bind = "0.0.0.0:55551"`（主服标准端口；query 端口按现状保持 `25565`）
- `online-mode = true`
- `force-key-authentication = false` —— 外置登录（LittleSkin/Yggdrasil）无 Mojang 签名公钥，必须关。
- `prevent-client-proxy-connections = false`
- `player-info-forwarding-mode = "modern"` + `forwarding-secret-file = "forwarding.secret"`（secret = `YyBxOhJZ9xJK`）
- `[servers]`：`survival = "127.0.0.1:30002"`、`minigames = "127.0.0.1:30003"`、`skyblock = "127.0.0.1:30004"`
- `try = ["survival"]`
- `accepts-transfers = false`
- `bungee-plugin-message-channel = true`（Advanced Portals 跨服门 `bungee:` 标签必需）
- **`[commands]` 命令转发段（跨服必配）**：`server = "velocity.command.server"`、`velocity = "velocity.command.velocity"`。缺此段时后端执行 `[player] server <子服>` 无从转发回代理，快捷菜单 / NPC 点击后静默无反应（详见 [游戏内传送、大厅、菜单等配置.md](./游戏内传送、大厅、菜单等配置.md) §3）。
- 基岩：`velocity/plugins/Geyser-Velocity/config.yml` 中 `bedrock.port = 19132`、`transport = nethernet`、`webrtc-port = 19132`
- 代理端权限：**`velocity/plugins/LuckPerms-Velocity-5.5.71.jar`**（独立实例，默认自带 H2，与后端 LuckPerms-Bukkit 数据不互通）。代理端无此插件则 `/server` 的权限校验无处生效。

### 4.2 后端子服（`server.properties`）
- `server-ip = 127.0.0.1`
- `online-mode = false`
- `prevent-proxy-connections = false`
- `enforce-whitelist = true` + `white-list = false`
- 端口与 `velocity.toml` 的 `[servers]` 严格一致

### 4.3 认证（`YggdrasilOfficialProxy.conf`）
- `api = "https://littleskin.cn/api/yggdrasil"`
- `authlib-injector = "./authlib-injector-1.2.8.jar"`、`edited = true`、`official-first = true`
- 代理端与三个后端各一份，端口见 §3.3

## 5. 转发与基岩互通基准

### 5.1 modern 转发配置（代理 ↔ 后端）
- Velocity：`player-info-forwarding-mode = "modern"` + `forwarding.secret` 文件 = `YyBxOhJZ9xJK`
- 三后端 `config/paper-global.yml`：`proxies.velocity.enabled: true` + `secret: YyBxOhJZ9xJK` + `online-mode: true`（注意在 `config/paper-global.yml`，非根目录 `paper.yml`）
- 三后端 `spigot.yml`：`bungeecord: false`（modern 与 legacy 互斥）
- **modern 转发核心**：Velocity `forwarding.secret` 文件 与 三后端 `proxies.velocity.secret` 必须一致（= `YyBxOhJZ9xJK`）。
- **Floodgate 基岩数据互通核心**：velocity 端 floodgate 与三后端 floodgate 的 `key.pem` 必须是同一份（四端 md5 一致，否则后端解密失败报 `Please connect through the official Geyser`）。
- ⚠ **Velocity 端 floodgate 在 modern 模式下【不要】配置 `forwarding-secret`**（那是 legacy/BungeeCord 模式专用，留着会让代理端改用 legacy 封装、与后端 modern 解析对不上）；三后端 floodgate 的 `forwarding-secret` 仅为 legacy 兼容冗余项，可保留。
- Velocity `online-mode = true` 与后端 `proxies.velocity.online-mode: true` 一致

### 5.2 基岩互通（Geyser-Velocity + floodgate）
- 基岩入口统一收口到 **Velocity 的 Geyser-Velocity（19132）**，玩家只连 `公网IP:19132`。
- Velocity 端 `velocity/plugins/floodgate/config.yml`：仅 `send-floodgate-data: true`（modern 模式靠 Velocity 的 modern forwarding + 本目录 `key.pem` 与后端互通，**不配置 `forwarding-secret`**）。
- 三后端 `plugins/floodgate/config.yml`：`key.pem` 与 velocity 端同一份（互通核心）；`forwarding-secret` 作为 legacy 兼容项保留即可。
- **后端禁用 Geyser-Spigot**（避免二次处理基岩协议、端口冲突、绕过代理）：`survival/plugins/` 下 `Geyser-Spigot.jar` → `Geyser-Spigot.jar.disabled`、`Geyser-Spigot/` → `Geyser-Spigot.disabled`。
- 两个独立层面：A. 基岩入口端口（Geyser 监听）；B. Velocity↔后端 modern 转发。禁用后端 Geyser（层面 A）不影响层面 B，两者都需正确配置。

### 5.3 基岩链路
```
基岩客户端 → 公网:19132 → Geyser-Velocity（终结基岩）
          → Velocity 以 modern 转发（签名 + floodgate 数据）
          → survival/minigames/skyblock 后端（proxies.velocity 验签 + floodgate 解密）→ 进服
```

## 6. 防火墙与安全基线

- **只放行**：`55551/TCP`（Java）、`19132/TCP+UDP`（基岩）。管理面板 `23333/24444` 仅本机可不外放。
- **绝不对外放行**：`30002~30004`（后端）、`32217~32220`（YOP agent）。它们绑 `127.0.0.1`，同机部署无需出网。
- **防直连**：后端 `online-mode=false` + modern 转发（`proxies.velocity` 已启用），绕过代理直连 `3000x` 的连接因缺代理签名被拒绝。
- **RCE/越权面收窄**：RCON 仅回环、管理端点关闭。
- **重复启动防护**：勿重复启动同一实例；YOP 端口冲突会导致外置登录整体失效。

## 8. 启动方式对照

| 方式 | 命令/文件 | 说明 |
| --- | --- | --- |
| 一键全套 | 根目录 `启动全套.bat` | 依次拉起 4 个窗口，双击即用；关窗口即停 |
| 单服 | 各目录 `start.bat` | 含 `cd /d "%~dp0"` + `pause`，适合手动调试 |
| MCSM 面板 | 填「直接的 java 命令」 | 不要填 `start.bat`/`启动全套.bat`（会派生脱离面板控制的子进程）；工作目录=各服根目录 |

> MCSM 启动命令：Java 绝对路径 + `-javaagent:YggdrasilOfficialProxy-2.3.0-paperclip.jar` + 终端编码 UTF-8；Velocity 关闭命令 `shutdown`。
> 启动顺序：survival → minigames → skyblock → Velocity，等各控制台 `Done (` 再放玩家。
> ⚠ 代理端新增 `LuckPerms-Velocity.jar` 与 `velocity.toml` 的 `[commands]` 段后，**必须重启 Velocity 才生效**（`/qm reload` 只重载后端菜单，不管代理）。重启后在代理控制台执行 [游戏内传送、大厅、菜单等配置.md](./游戏内传送、大厅、菜单等配置.md) §3 的 `lp` 授权命令。

## 9. 游戏内跨服（指向专文）

玩家在游戏内怎么从主城去其它子服，属于**玩法配置**，不在本文重复。唯一真源：

| 入口 | 文档 |
| --- | --- |
| 走过去触发的传送门 | [传送门-Advanced Portals.md](./传送门-Advanced Portals.md) |
| 菜单 / NPC / 三服菜单分工 / 小游戏地图 / 跨服权限三件套 | [游戏内传送、大厅、菜单等配置.md](./游戏内传送、大厅、菜单等配置.md) |

两条链路的**网络侧区别**（本文只保留这一条结论）：

- **Advanced Portals `bungee:`** 由后端向 `BungeeCord` 通道发 `Connect` 消息，Velocity 兼容通道直接换服，**只需** `bungee-plugin-message-channel = true`（§4.1）。
- **QuickMenu / FancyNpcs** 是后端执行 `/server <子服>` 再转发回代理，才需要 `[commands]` + `LuckPerms-Velocity` + `velocity.command.server` 授权（§4.1）。

> 排错别混用：传送门走进去无反应，先查 `bungee-plugin-message-channel` 与 `[servers]` 名字；
> 菜单 / NPC 点击无反应，才查命令转发三件套。
