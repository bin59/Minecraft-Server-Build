# LuckPerms 权限组设计方案

> 针对「南瓜生存服」当前插件组合定制的完整权限方案。
>
> 配套文件：
> - [`config.yml`](config.yml) — 可直接放入 `plugins/LuckPerms/` 的主配置
> - [`权限导入脚本.txt`](权限导入脚本.txt) — 一键执行的 `lp` 命令集
> - [`权限节点速查.md`](权限节点速查.md) — 按插件的权限节点对照表
> - [`LuckPerms.md`](LuckPerms.md) — 插件基础说明与常用命令

**适配范围**：EssentialsX · Residence · CoreProtect · SkinsRestorer · OpenInv · spark · Geyser · Floodgate · ViaVersion · EasyBot · Simple Voice Chat · Chunky · BedrockPlayerSupport · WorldEdit · Vault

## 一、设计原则

| 原则 | 说明 |
|---|---|
| **最小权限** | 每组只给它"必须用的"，管理权限一律不下放给玩家组 |
| **双线继承** | 生存线（会员/赞助）与管理线（协管/管理/服主）分开，互不污染 |
| **权重驱动前缀** | 主组由 `parents-by-weight` 计算，前缀靠 `setweight` 竞争，避免手写主组 |
| **OP 不下放** | `auto-op: false`，管理员靠权限节点而非 OP，便于审计 |
| **危险命令隔离** | `/ban` `/mute` `/jail` 只给 admin+；`helper` 只能查、不能罚 |
| **审计类只读** | CoreProtect 的 `lookup/inspect` 与 `rollback/purge` 严格分开设给不同组 |

### 组定义表

| 组名 | 权重 | 前缀 | 继承 | 定位 | 典型获得方式 |
|---|---:|---|---|---|---|
| `default` | 1 | `&8[&7新手&8]&r` | — | 刚进服，只能基础生存 | 自动（LuckPerms 默认组） |
| `member` | 5 | `&8[&a成员&8]&r` | default | 正式成员，多家园、可用传送 | 管理员手动提升 / 在线时长达标 |
| `vip` | 20 | `&8[&6VIP&8]&r` | member | 赞助玩家，飞行、绕过冷却 | 赞助 |
| `mvp` | 30 | `&8[&bMVP&8]&r` | vip | 高级赞助，更多领地与家园 | 赞助 |
| `helper` | 50 | `&8[&9协管&8]&r` | member | 实习管理：可查可调解，**不可处罚** | 任命 |
| `admin` | 80 | `&8[&c管理&8]&r` | helper | 管理员：完整管理工具 | 任命 |
| `owner` | 100 | `&8[&4服主&8]&r` | admin | 服主：全部权限 + OP | 服主本人 |

> **注意**：`helper` 继承 `member` 而非 `vip`，因此协管不会自动获得飞行等赞助特权——管理权限与赞助特权解耦。
> 若希望协管也能飞，单独给 `helper` 加 `essentials.fly` 即可（脚本中已注释，按需开启）。

## 四、EssentialsX 家园数量与 Residence 领地组映射

### 4.1 家园数量（`essentials.sethome.multiple.<n>`）

| 组 | 权限节点 | 数量 |
|---|---|---:|
| default | `essentials.sethome.multiple.1` | 1 |
| member | `essentials.sethome.multiple.3` | 3 |
| vip | `essentials.sethome.multiple.6` | 6 |
| mvp / helper / admin / owner | `essentials.sethome.multiple.unlimited` | 无限 |

> EssentialsX 取**所有可用节点中的最大值**，因此不要给低权重组更高的数字。
> `sethome-multiple` 在 `plugins/Essentials/config.yml` 里也有默认值，权限节点优先。

### 4.2 Residence 领地组（`residence.group.<name>`）

Residence 通过权限节点 `residence.group.<组名>` 决定玩家使用 `plugins/Residence/groups.yml` 中的哪一组限制。

**当前 `groups.yml` 只有 `Default` 和 `NextGroup` 两组**，需要按本方案扩充。推荐的 `groups.yml` 组名与 LuckPerms 映射：

| LuckPerms 组 | Residence 组 | 权限节点 | MaxResidences | MaxEastWest / MaxNorthSouth | SubzoneDepth |
|---|---|---:|---:|---:|---:|
| default | `default` | `residence.group.default` | 1 | 100 | 2 |
| member | `member` | `residence.group.member` | 3 | 150 | 3 |
| vip | `vip` | `residence.group.vip` | 6 | 200 | 4 |
| mvp | `mvp` | `residence.group.mvp` | 10 | 256 | 5 |
| helper | `helper` | `residence.group.helper` | 10 | 200 | 5 |
| admin / owner | `admin` | `residence.group.admin` | 9999 | 2048 | 8 |

> ⚠️ **两个易踩的坑**
> 1. **组名大小写**：Residence 匹配时会转小写，请直接把 `groups.yml` 里的组名写成**全小写**（`default` / `member` / `vip` …），不要用 `Default`。
> 2. **只在 `groups.yml` 里加组不会生效**：必须同时在 LuckPerms 里给对应组 `residence.group.<名称>` 权限，否则玩家仍落到 `groups.yml` 的 `Default` 组。

对应的 `groups.yml` 片段（在 `Groups:` 下新增，可复制 `Default` 段后改数值）：

```yaml
Groups:
  default:            # ← 原 Default 改名小写，或保留并新增下面的组
    Residence:
      CanCreate: true
      MaxResidences: 1
      MaxAreasPerResidence: 2
      MaxEastWest: 100
      MaxNorthSouth: 100
      MaxUpDown: 384
      SubzoneDepth: 2
      MaxSubzonesInArea: 3
      CanTeleport: true
      Unstuck: true
      Kick: false
    # ... 其余沿用原 Default 段
  member:
    Residence:
      CanCreate: true
      MaxResidences: 3
      MaxAreasPerResidence: 3
      MaxEastWest: 150
      MaxNorthSouth: 150
      MaxUpDown: 384
      SubzoneDepth: 3
      MaxSubzonesInArea: 5
      CanTeleport: true
      Unstuck: true
      Kick: false
  vip:
    Residence:
      CanCreate: true
      MaxResidences: 6
      MaxAreasPerResidence: 5
      MaxEastWest: 200
      MaxNorthSouth: 200
      MaxSubzonesInArea: 8
      SubzoneDepth: 4
  admin:
    Residence:
      CanCreate: true
      MaxResidences: 9999
      MaxAreasPerResidence: 50
      MaxEastWest: 2048
      MaxNorthSouth: 2048
      SubzoneDepth: 8
      MaxSubzonesInArea: 50
      Kick: true
```

> 改完后 **服务端控制台**执行 `/res reload groups`（注意：用 `/res reload` 可能不重载 groups，用控制台更稳妥），详见 [2-玩法与玩家功能插件/04-领地系统-Residence](../../3-玩法与玩家功能插件/04-领地系统-Residence/Residence.md)。

## 五、基岩版（Floodgate）玩家的特殊处理

### 5.1 关键事实

> ⚠️ **Floodgate 本身不会向 LuckPerms 注册 `floodgate` 上下文。**
> 网上流传的「用 `/lp group X permission set xxx true floodgate=true` 给基岩玩家单独设权限」**在默认安装下不生效**，除非额外装了提供该 context 的插件（如 FloodgateExtras）。

因此本方案采用**独立组 + 自动分配**的做法，最稳。

### 5.2 推荐方案：`bedrock` 附加组

创建一个**不带前缀、权重 0** 的附加组 `bedrock`，专门承载基岩版专属权限（如 BedrockPlayerSupport 的 GUI 表单）。

```
bedrock（权重 0，无前缀）
├── bedrockplayersupport.tpgui
├── bedrockplayersupport.homegui
├── bedrockplayersupport.msggui
├── bedrockplayersupport.kitgui
├── bedrockplayersupport.warpgui
└── 可选：essentials.chat.color 关闭（基岩客户端输入 § 不便）
```

权重设为 0 且**不设前缀**，这样它不会干扰主组前缀的计算（[基岩] 标签若要显示，用 `meta addprefix` 追加而非 `setprefix`）。

**自动分配的三种做法**（推荐第一种）：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. BedrockPlayerManager**（推荐） | 装 ofunny 的 [Bedrock Player Management for Floodgate](https://www.spigotmc.org/resources/bedrock-player-managment-for-floodgate-geyser.82278/)，配置 `permissions.enabled: true`、`bedrock_group_name: "bedrock"` | 全自动，玩家进出服自动加/撤组 | 多装一个插件 |
| **B. 手动命令** | 基岩玩家首次进服后，服主执行 `/lp user <名字> parent add bedrock` | 零依赖 | 需要人工，玩家多时累 |
| **C.  Floodgate `default-group`** | 部分 Floodgate 版本/附加组件支持在 `plugins/floodgate/config.yml` 设 `default-group: bedrock` | 最省事 | **版本相关，不一定存在**，需自己确认 |

### 5.3 基岩版玩家名前缀

基岩玩家经 Floodgate 后名字带 `.` 前缀（如 `.Steve`），这是 Floodgate 的 `username-prefix` 设置，**与 LuckPerms 无关**，在 `plugins/floodgate/config.yml` 中修改。

若想在聊天里区分 Java / 基岩玩家，可给 `bedrock` 组加一个**追加前缀**：

```
/lp group bedrock meta addprefix 5 "&8[&7BE&8] "
```

> 用 `addprefix` 而不是 `setprefix`，它会叠加在主组前缀后面，不影响 `[VIP]` 之类的显示。

## 六、部署步骤

### 第 0 步：确认 LuckPerms 主 JAR 存在（P0 前置）

> ⚠️ 当前 `plugins/LuckPerms/` 下**缺少主插件 JAR**（`LuckPerms-Bukkit-*.jar`），只有配置和数据库。
> 先从 https://luckperms.net/download 下载放入 `plugins/` 并重启，否则后面所有步骤都执行不了。

### 第 1 步：放入 config.yml

```powershell
# 用本目录下的 config.yml 覆盖
copy "5-服务器管理/01-权限管理系统-LuckPerms\config.yml" "C:\mc_serve\1.21.11-test\plugins\LuckPerms\config.yml"
```

> 覆盖前先备份原文件。若担心版本差异，可改为对照本文件**手动修改**原 config.yml 中对应的项。

### 第 2 步：执行导入脚本

在**服务端控制台**（不是游戏内聊天框）逐段粘贴 [`权限导入脚本.txt`](权限导入脚本.txt) 的内容。

> 控制台粘贴比游戏内更稳：不受聊天长度限制、不受权限不足阻断。
> 脚本已写成幂等形式（重复执行不会报错或产生重复权限）。

### 第 3 步：设置默认组

```bash
/lp group default meta setprefix 1 "&8[&7新手&8]&r"
# 确认新玩家自动进 default 组（LuckPerms 默认行为，一般无需改）
/lp info
```

### 第 4 步：同步 Residence groups.yml

按 [4.2](#42-residence-领地组residencegroupname) 修改 `plugins/Residence/groups.yml`，然后：

```bash
/res reload groups
```

### 第 5 步（可选）：基岩版自动分组

按 [5.2](#52-推荐方案bedrock-附加组) 选择方案 A / B / C 之一。

### 第 6 步：迁移已有玩家

```bash
# 查看某玩家当前所在组
/lp user <玩家> info

# 把已有玩家迁移到新组（示例：把老玩家批量放到 member）
/lp user <玩家> parent set member

# 批量：把所有无任何组的玩家设为 default（一般不需要）
# /lp bulkupdate all delete group
```

## 八、常见故障

| 现象 | 原因 | 解法 |
|---|---|---|
| 加了权限还是提示无权限 | ① 没重载 ② 插件在 LuckPerms 之后加载 ③ 权限节点名写错 | `/lp reload`；`/lp user <玩家> permission check <节点>` 逐个验证 |
| 前缀只显示默认组的 | 主组计算错误 | 确认 `primary-group-calculation: parents-by-weight`，且各组 `setweight` 已设 |
| 玩家同时有两个前缀 | 用了 `setprefix` 而非 `addprefix`，或继承了多个带前缀的组 | 只给"主链"上的组 `setprefix`，附加组用 `addprefix` 或权重 0 |
| `residence.group.vip` 不生效 | `groups.yml` 里组名大小写不符 / 未 `/res reload groups` | 组名全小写；控制台执行 `/res reload groups` |
| 家园数量不对 | EssentialsX 取最大值，某组给了更高的 `multiple.<n>` | `/lp user <玩家> permission check essentials.sethome.multiple.*` 排查 |
| 基岩玩家没 GUI | Floodgate 不会自动分到 `bedrock` 组 | 按 [5.2](#52-推荐方案bedrock-附加组) 方案 A 或 B 处理 |
| `/lp` 命令无反应 | 主 JAR 缺失（P0） | 下载 `LuckPerms-Bukkit-*.jar` 放入 `plugins/` |

## 九、备份与恢复

```bash
# 导出（JSON 快照，含全部组/玩家/权限）
/lp export 权限备份-<日期>

# 导入（会覆盖现有数据，谨慎）
/lp import 权限备份-<日期>

# 文件级备份（更彻底，含数据库）
#   停服后打包 plugins\LuckPerms\ 整个目录
```

> `auto-save` 默认在每次权限变更后落盘（h2）。大批量导入脚本执行完后建议手动导出一次快照。
