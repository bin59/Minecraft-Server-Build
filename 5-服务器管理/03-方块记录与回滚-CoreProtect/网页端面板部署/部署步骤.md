# CoLWI 网页端查询面板 — 部署文档

本文档记录 CoLWI（CoreProtect Lookup Web Interface）CommunityCraft rework 版在 Ubuntu/Debian 配合 Nginx 环境下的完整部署流程。内容包括环境要求、部署前配置清单、一键脚本部署、非 apt 系手动部署、安全加固、验收标准与故障排查，目标读者是负责搭建 CoreProtect 网页查询面板的服主或运维人员。

> 适用对象：CoreProtect Lookup Web Interface（CoLWI）**CommunityCraft rework for CoreProtect 23.2**
> 目标路径：`/var/www/CoreProtect-Lookup-Web-23.2`
> 配套文件：`deploy.sh`（一键脚本）、`nginx-colwi.conf.example`（Nginx 站点模板）

---

## 1. 这套东西是什么

CoreProtect **本体没有网页端**，只有游戏内 `/co lookup`。CoLWI 是第三方 PHP 程序，**直接读 CoreProtect 的数据库表**，在浏览器里按动作 / 玩家 / 方块 / 时间 / 坐标查记录。

- 只读：**不能回滚**，恢复仍要在游戏内执行 `/co rollback`
- 项目：https://github.com/CommunityCraftMC/CoreProtect-Lookup-Web
- ⚠️ rework **已移除内置登录**，访问控制必须由 Web 服务器层提供

## 2. 环境要求

| 项目 | 要求 | 检查命令 |
| --- | --- | --- |
| 系统 | Ubuntu 20.04 / 22.04 / 24.04，Debian 11 / 12 | `cat /etc/os-release` |
| Web 服务器 | Nginx（脚本默认） | `nginx -v` |
| PHP | **8.4 为上游验证版本**，8.1+ 一般可用 | `php -v` |
| PHP 扩展 | `PDO` + `pdo_mysql`（MySQL）或 `pdo_sqlite`（SQLite） | `php -m \| grep -i pdo` |
| 数据库 | CoreProtect v23.2+ 的库 | — |
| SQLite 特例 | **网页服务器必须与 MC 服务器同机** | — |
| 工具 | `htpasswd`、`curl` | — |
| 权限 | root | `id -u` |

> 非 apt 系（CentOS / RHEL / Rocky）：脚本 `install_deps` 会直接退出，请走 [§6 手动部署](#6-手动部署已有-nginx-或非-apt-系)。

## 3. 部署前准备清单

先把下面这张表填好，部署时直接照抄：

| 项 | 填写 | 对应脚本变量 |
| --- | --- | --- |
| 程序目录 | `/var/www/CoreProtect-Lookup-Web-23.2` | `WEB_ROOT` |
| 对外端口 | 例 `18443`（别用 80 默认） | `LISTEN_PORT` |
| 域名 | 无则填 `_` | `DOMAIN` |
| 数据库类型 | `mysql` / `sqlite` | `DB_TYPE` |
| MySQL 地址 | `127.0.0.1:3306` | `DB_HOST` |
| 库名 | `coreprotect` | `DB_NAME` |
| 只读账号 / 密码 | `corelook` / `****` | `DB_USER` / `DB_PASS` |
| 表前缀 | 与 `config.yml` 的 `table-prefix` 一致，通常 `co_` | `DB_PREFIX` |
| SQLite 路径 | 如 `/mc/plugins/CoreProtect/database.db` | `SQLITE_PATH` |
| 访问控制 | `auth` / `ip` / `both` | `ACCESS_MODE` |
| 登录账号 / 密码 | 密码留空则脚本随机生成 | `AUTH_USER` / `AUTH_PASS` |
| 白名单 IP | 你的出口公网 IP，空格分隔 | `ALLOW_IPS` |
| HTTPS | 有域名且 80 可达才开 `yes` | `ENABLE_HTTPS` |

**先建只读数据库账号（MySQL）**：

```sql
CREATE USER 'corelook'@'网页服务器IP' IDENTIFIED BY '强密码';
GRANT SELECT ON coreprotect.* TO 'corelook'@'网页服务器IP';
FLUSH PRIVILEGES;
```

> 网页端只做查询，**只给 SELECT 就够**。若 MySQL 与 MC 同机，host 填 `localhost` 或 `127.0.0.1`。

## 4. 快速部署（脚本方式）

### 4.1 上传

```bash
# 程序本体（已上传）
ls /var/www/CoreProtect-Lookup-Web-23.2
# 应看到：index.php  lookup.php  config.php  （可能还有 res/、cache/、tests/）

# 上传脚本
# 用 scp / SFTP 把 deploy.sh 放到服务器任意位置，例如 /root/deploy.sh
```

### 4.2 Windows 编辑过的脚本先去 CRLF

```bash
sed -i 's/\r$//' /root/deploy.sh     # 或 dos2unix /root/deploy.sh
```

### 4.3 改配置区

```bash
vi /root/deploy.sh    # 只改文件顶部「必填配置区」那一段
```

### 4.4 执行

```bash
chmod +x /root/deploy.sh
sudo bash /root/deploy.sh
```

### 4.5 三种模式

| 命令 | 用途 |
| --- | --- |
| `sudo bash deploy.sh` | 完整部署；幂等，可重复跑 |
| `sudo bash deploy.sh verify` | 只体检，不改任何文件 |
| `sudo bash deploy.sh conf` | 只重生成 Nginx 站点并 reload |

## 5. 脚本各阶段详解

| # | 阶段 | 做了什么 |
| --- | --- | --- |
| 0 | 前置校验 | 必须 root；`WEB_ROOT` 下必须同时有 `index.php`、`lookup.php`、`config.php` |
| 1 | 装依赖 | `nginx php-cli php-fpm php-mysql php-sqlite3 apache2-utils curl` |
| 2 | PHP 体检 | 取 PHP 版本；< 8.1 告警，≠ 8.4 提示；校验 PDO 与目标驱动已加载 |
| 3 | 权限 | `chown -R root:www-data`；目录 750 / 文件 640；`cache/` 770 |
| 4 | 写 config | 见下节，**只改已存在的键**，改前备份 |
| 5 | Nginx | 生成 `/etc/nginx/sites-available/colwi.conf` 并软链到 `sites-enabled`；`nginx -t` 校验 |
| 6 | 访问控制 | 创建 `/etc/nginx/.colwi_htpasswd`；按 `ACCESS_MODE` 写 `auth_basic` / `allow-deny` |
| 7 | 防火墙 | `ufw` 处于 active 时放行 `LISTEN_PORT/tcp` |
| 8 | HTTPS | `ENABLE_HTTPS=yes` 时 certbot 签证书并强制跳 HTTPS |
| 9 | 自检 | 见 [§8 验证与验收](#8-验证与验收) |

### 5.1 config.php 是怎么被改的

脚本生成一个临时 PHP 补丁（`<<'PHPEOF'` 内联，不落盘到 web 目录），逻辑是：

- 正则定位 `'server' => [ ... ]` 块
- **只替换块内已存在的键**，`type / host / database / username / password / path / prefix / preBlockName / mapLink`
- 找不到的键 → 列到 `missing` 并**跳过**，不会凭空插入结构
- 改前 `copy()` 备份为 `config.php.bak.<YYYYmmddHHMMSS>`
- 改完跑 `php -l`，语法错就报错退出

等价的 MySQL 段（手工填也照这个写）：

```php
'server' => [
    'type'        => 'mysql',
    'host'        => '127.0.0.1:3306',
    'database'    => 'coreprotect',
    'username'    => 'corelook',
    'password'    => '只读账号密码',
    'flags'       => '',
    'prefix'      => 'co_',
    'preBlockName'=> true,
    'mapLink'     => '',
],
```

SQLite 段：

```php
'server' => [
    'type'        => 'sqlite',
    'path'        => '/mc/plugins/CoreProtect/database.db',
    'prefix'      => 'co_',
    'preBlockName'=> true,
    'mapLink'     => '',
],
```

查询安全阀（在 `config.php` 的 `form` 段，脚本不改，建议手调）：

```php
'form' => [
    'count' => 30,                    // 默认每页
    'moreCount' => 10,                // 加载更多
    'max' => 300,                     // 单次查询上限
    'maxCoordinateVolume' => 5000000, // 坐标选区体积上限，0=不限
    'timeoutSeconds' => 20,           // 查询超时，0=不限
],
```

## 6. 手动部署（已有 Nginx 或非 apt 系）

1. 装 Web 栈（以 CentOS 为例）：

   ```bash
   dnf install -y nginx php-fpm php-mysqlnd php-pdo
   systemctl enable --now nginx php-fpm
   ```

2. 放程序并收权限：

   ```bash
   chown -R root:nginx /var/www/CoreProtect-Lookup-Web-23.2
   find /var/www/CoreProtect-Lookup-Web-23.2 -type d -exec chmod 750 {} \;
   find /var/www/CoreProtect-Lookup-Web-23.2 -type f -exec chmod 640 {} \;
   [ -d /var/www/CoreProtect-Lookup-Web-23.2/cache ] && chmod 770 /var/www/CoreProtect-Lookup-Web-23.2/cache
   ```

3. 复制 `nginx-colwi.conf.example` 到 `/etc/nginx/conf.d/colwi.conf`，改 4 处：端口、`server_name`、`root`、`fastcgi_pass` 的 PHP 版本。

4. 建 Basic Auth：

   ```bash
   htpasswd -bc /etc/nginx/.colwi_htpasswd cpadmin '你的密码'
   chmod 640 /etc/nginx/.colwi_htpasswd
   ```

5. 按 [§5.1](#51-configphp-是怎么被改的) 手工改 `config.php`。

6. 校验并生效：

   ```bash
   nginx -t && systemctl reload nginx
   ```

7. **SELinux**（CentOS 若开启 Enforcing）：

   ```bash
   setsebool -P httpd_can_network_connect_db 1      # 允许 PHP 连 MySQL
   chcon -R -t httpd_sys_content_t /var/www/CoreProtect-Lookup-Web-23.2
   # cache/ 若要可写：chcon -R -t httpd_sys_rw_content_t .../cache
   ```

## 7. 安全加固清单

| # | 项 | 为什么 |
| --- | --- | --- |
| 1 | 必须开访问控制 | rework **已移除内置认证**，无防护 = 全服玩家坐标/行为/聊天裸奔 |
| 2 | 库账号只给 `SELECT` | 网页端不需要写库，最小权限 |
| 3 | 别用 80/443 默认端口 | 减少扫描器命中 |
| 4 | `deny` 掉 `config.php` / `.git` / `tests` / `.env` | 防止数据库凭据与源码泄露 |
| 5 | 日志单独存放 | `/var/log/nginx/colwi.*.log`，便于审计谁查了什么 |
| 6 | 不给普通玩家开放 | 记录含隐私数据，仅服主 / 管理组 |
| 7 | 定期备份 `config.php` | 脚本每次改都会留 `.bak.*`，清理时别误删 |
| 8 | 有域名就上 HTTPS | Basic Auth 明文传密码，HTTP 下等于裸奔 |

## 8. 验证与验收

脚本结束会自动跑一遍，也可以单独执行 `sudo bash deploy.sh verify`：

```bash
# 1. 语法
php -l /var/www/CoreProtect-Lookup-Web-23.2/index.php
php -l /var/www/CoreProtect-Lookup-Web-23.2/lookup.php

# 2. 服务
systemctl is-active nginx && systemctl is-active php$(php -r 'echo PHP_MAJOR_VERSION.".".PHP_MINOR_VERSION;')-fpm

# 3. 未带认证应返回 401
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18443/index.php

# 4. 带认证应返回 200
curl -s -o /dev/null -w '%{http_code}\n' -u cpadmin:密码 http://127.0.0.1:18443/index.php

# 5. config.php 必须 403/404
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18443/config.php
```

期望结果：

| 检查 | 期望 |
| --- | --- |
| `php -l` × 2 | No syntax errors |
| nginx / php-fpm | `active` |
| 未认证访问 | `401` |
| 带认证访问 | `200` |
| `config.php` | `403` 或 `404` |

浏览器打开 `http://服务器IP:端口/`，输入 Basic Auth 账号，随便查一次（例如按玩家名 + 时间 1d），能出记录即为部署完成。

## 9. 常见故障

| 现象 | 原因 / 处理 |
| --- | --- |
| `请用 root 执行` | 加 `sudo` |
| `目录里缺少 xxx，上传不完整` | 重新上传，确认 `index.php` / `lookup.php` / `config.php` 都在 |
| `本脚本只支持 apt 系` | 走 [§6 手动部署](#6-手动部署已有-nginx-或非-apt-系) |
| `扩展 pdo_mysql 未加载` | 装 `php-mysql` 并在 php.ini 打开扩展，重启 php-fpm |
| `config.php 里未找到 'server' => [...] 块` | 版本结构不同，手工改并核对 [§5.1](#51-configphp-是怎么被改的) |
| `missing` 里列了键 | 该键原文件没有，脚本跳过；手工补进 `server` 段 |
| 页面 502 | `fastcgi_pass` 的 socket 路径与 PHP 版本不符，查 `ls /run/php/*.sock` |
| 页面 500 / 空白 | 看 `tail -50 /var/log/nginx/colwi.error.log` |
| 能打开但查不到数据 | 库名/前缀错、账号没 `SELECT`、CoreProtect 还没写入、SQLite 指向了副本 |
| `unsupported schema` | 缺 v23.2 新表/列（v24.0 新记录），上游适配滞后，先用 `/co lookup` |
| `Query too large` / `Query timed out` | 缩小选区，或调 `form.max` / `maxCoordinateVolume` / `timeoutSeconds` |
| 未认证访问返回 200 | **危险**：访问控制没生效，检查 `auth_basic` 是否被上层 `server` 块覆盖 |
| `config.php` 返回 200 | **危险**：凭据泄露，立刻检查 `location ~ /(config\.php|...)` 是否生效 |
| CentOS 上连不上 MySQL | SELinux：`setsebool -P httpd_can_network_connect_db 1` |

## 10. 更新与卸载

**更新（git 安装）**：

```bash
cd /var/www/CoreProtect-Lookup-Web-23.2
git stash && git pull && git stash pop
# 冲突时：手动编辑 config.php（找 <<<<<<< ======= >>>>>>>）后 git add config.php
```

**更新（zip 安装）**：重新下载解压，**手动把旧 `config.php` 迁移过去**——脚本不会帮你做这件事。

**卸载**：

```bash
rm -f /etc/nginx/sites-enabled/colwi.conf /etc/nginx/sites-available/colwi.conf
rm -f /etc/nginx/.colwi_htpasswd
nginx -t && systemctl reload nginx
# 程序目录按需保留或删除
```

## 11. 版本兼容提醒

- rework 明确面向 **CoreProtect v23.2** 数据库结构。本服文档标注的是 **CE v24.0**，v24 新增/调整的记录类型可能查不出来。
- 面板带 **schema 能力检测**，缺表缺列时返回清晰的 JSON 不支持提示，而不是裸 SQL 报错。
- 依赖的默认表：`co_block` `co_container` `co_item` `co_sign` `co_chat` `co_command` `co_session` `co_username_log` `co_user` `co_world` `co_material_map` `co_entity_map`（可选 `co_blockdata_map`）。
- 兜底：查不出来就用游戏内 `/co lookup`。
