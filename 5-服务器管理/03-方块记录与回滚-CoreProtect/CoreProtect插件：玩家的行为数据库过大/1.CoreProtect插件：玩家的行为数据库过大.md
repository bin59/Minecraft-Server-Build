> **适用版本**：CoreProtect CE v24.0（最新 Community Edition）  |  MC 1.16.5+

---

`CoreProtect/database` 数据库文件过大，是很多服主都会遇到的问题。这是因为它事无巨细地记录了所有玩家的行为，日积月累自然就变大了。可根据情况选择以下清理与优化方案。

---

### 🧹 方案一：手动清理（最直接有效）

这是最快速、最直接的瘦身方法，通过命令删除不需要的历史数据。

1.  **基础清理命令**
    在游戏内或服务器控制台输入以下命令：
    ```
    /co purge t:<时间>
    ```
    例如，`/co purge t:30d` 会**永久删除**所有30天前的数据，只保留最近一个月的数据。

    *   **注意**：在游戏内执行时，时间参数**不能少于 30 天**（v24.0 已加入参数校验，无效参数会直接提示）。
    *   支持的时间格式：`30d` (天), `12w` (周), `6mo` (月)。

2.  **进阶优化命令（强烈推荐）**
    v24.0 中 `#optimize` 为内置功能，清理后加上即可**重整数据库文件，真正释放被占用的硬盘空间**：
    ```
    /co purge t:30d #optimize
    ```
    *   **注意**：加上 `#optimize` 后，清理过程会**显著变慢**（v24.0 回滚性能虽提升约 80%，优化仍需要时间），请耐心等待，**不要中途强制停止服务器**。

---

### 🤖 方案二：自动清理（一劳永逸）

如果你不想定期手动操作，可以设置自动清理。

1.  **使用插件内置功能（Patreon 订阅专属）**
    `auto-purge` 是 CoreProtect v24.0 新增的内置功能，但标注为 **Patreon 订阅者专属**（带 `*` 号），CE（免费版）**不可用**。
    *   如果你有 Patreon 订阅，在 `plugins/CoreProtect/config.yml` 中添加或修改：
      ```yaml
      auto-purge: 180d       # 每天自动清理 180 天前的数据
      auto-purge-time: "03:30" # 每天执行时间（24小时制）
      ```
    *   路径：`plugins/CoreProtect/config.yml`。

2.  **使用第三方插件（CE 免费版替代方案）**
    如果用的是 CE 免费版，可以安装额外的插件（如 `CoreProtectClean`、`AutoPurge` 等）来实现定时自动清理。不过，这类插件可能不是官方出品，稳定性需要自己评估，**不建议直接在大型生产环境使用**。

---

### ⚙️ 方案三：修改配置文件（辅助）

通过修改 `config.yml` 中的 `keep-days` 选项，设置默认查询/回滚的时间上限（注意：**v24.0 CE 免费版中此选项不自动清理数据**，仅影响 `/co lookup` 等查询的默认时间范围）。

```yaml
# plugins/CoreProtect/config.yml
keep-days: 30  # 查询默认只显示 30 天内的记录
```

> 如果确实需要自动清理，请参考方案二。

---

### 🗄️ 方案四：切换数据库类型（进阶）

数据库量大后 SQLite 查询/回滚会明显变慢，生产环境建议切换 MySQL（v24.0 大幅改进了 MySQL 索引处理）。完整四步迁移教程（建库建用户 → 改配置 → 迁移数据 → 验证清理）见同目录 2.将CoreProtect从SQLite切换到MySQL.md。

### 🎯 方案五：阻断漏斗/发射器伪用户刷库（hopper 刷库专项）

**典型症状**：数据量猛增，`/co lookup` 结果中 91% 记录来自 `#hopper`、`#dispenser` 伪用户（漏斗/发射器**自动传输**），主因物品大量 `minecraft:minecart`——典型场景是**矿车在漏斗轨道上循环**，每转一圈触发多次传输，一次在线时段就能刷出数万条记录（如某时段 8.3 万次操作）。

**方法 A：黑名单跳过自动传输（推荐，保留玩家手动记录）**

官方黑名单文件 `plugins/CoreProtect/blacklist.txt`（无则新建），每行一个条目：

```
#hopper
#dispenser
#dropper
```

`#` 开头为**伪用户**（非真实玩家）：分别是漏斗、发射器、投掷器自动传输的记录来源。加入后这些来源的记录**完全不写入**，而玩家手动开关容器、取放物品的记录（归玩家名下）**不受影响**。改完执行 `/co reload` 生效，无需重启。

**方法 B：彻底关闭漏斗交易记录**

`config.yml`：

```yaml
hopper-transactions: false # 所有漏斗交易（含自动传输）不再记录
```

更彻底，但玩家经漏斗转移的物品也会丢记录，物品类回滚会缺这部分数据。适合不依赖漏斗物品回滚的服。

**方法 C：组合**：先按方法 A 跳过 `#hopper`/`#dispenser`/`#dropper`，若仍有玩家名下的大批量记录再评估方法 B。矿车循环属合法机器玩法，一般不动玩家设计。

**已有数据清理**：历史囤积的伪用户记录用 `/co purge` 按时间批量删除（见方案一），如 `/co purge t:30d #optimize`；CoreProtect 支持按用户清理（`/co purge u:<玩家或伪用户>`，具体语法以游戏内 `/co help` 为准）。

### 💡 预防与注意事项

*   **从源头减少记录**：实体（生物）占用的数据库空间约是方块的 **5 倍**。v24.0 新增了大量实体行为记录（村民闲聊、工作地点记忆、鸡蛋投掷、蠹虫虫蚀等），如果服务器有大量村民/生物农场，建议使用黑名单 (`blacklist.txt`) 排除无关区域或生物，有效减缓数据库增长速度。
*   **v24.0 新增的记录类型**（这些都会占用数据库空间，按需调整 `config.yml` 中的开关）：
    - 僵尸破门、花入花盆、掉落物进入漏斗
    - 点燃的 TNT 消失、火焰熄灭
    - 抛出的鸡蛋、村民闲聊（gossip）
    - 村民工作地点记忆、村民被闪电劈死
    - 自定义头颅贴图、所有蠹虫虫蚀过程
*   **操作前务必备份**：在执行任何清理或数据库切换操作前，**请一定先完整备份**你的 `CoreProtect` 文件夹。数据一旦删除将**无法恢复**。
*   **清理后空间未立即释放**：不带 `#optimize` 的清理不会缩小数据库文件 — 删除的数据留下"空洞"，新数据会优先填充。使用 `#optimize` 才能真正回收硬盘空间。
*   **v24.0 性能提升**：回滚性能提升约 80%，漏斗和容器交易记录性能也显著优化，日常使用体验更流畅。
