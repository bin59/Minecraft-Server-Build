# 南瓜账本 MoneyLedger（自研插件）

> 定位：把南瓜币的每一笔变动按类别记下来——**转账 / 买卖 / 拍卖 / 每日收购 / 周税 / 任务 / 活动 / 活动参与**，可查单个玩家、按类别筛、导出 CSV。长期复用，装上就自动开始记。
> 适用：Leaf / Paper 1.21.11，依赖 EssentialsX（作为经济账本）。

> **部署状态（2026-10-04 核对）**：本插件**已部署**到运行服 `plugins\MoneyLedger.jar`（部署时间 2026-10-04 01:33），随服自动记账。运行服已装 `EssentialsX-2.22.1-dev+25-cfb6f12.jar`，满足运行依赖。

## 一、安装

1. 把 **`MoneyLedger.jar`** 拷到运行服 `plugins/` 目录。
2. **完全重启服务端**。
3. 启动后自动生成 `plugins/MoneyLedger/config.yml` 与 `plugins/MoneyLedger/ledger.db`（SQLite 数据库）。
4. 无需配置，装上即开始记录每一笔南瓜币变动。

> 依赖：需要 **EssentialsX** 先加载（本插件监听它的余额变动事件）。发奖的 PumpkinMail 也建议同服，方便把活动发奖归入"活动/管理"。

## 二、管理端命令（权限 `moneyledger.admin`，OP 默认）

```text
/moneyledger recent <玩家> [类别]     # 查看某人最近流水，可加类别过滤
/moneyledger summary <玩家>            # 某人按类别汇总（正=入、负=出）
/moneyledger export [玩家]             # 导出 CSV（省略玩家=全部）
/moneyledger stats                     # 总记录笔数
```

别名：`/moneylog`。类别支持中文或英文（转账/买卖/拍卖/每日收购/周税/任务/活动/出售/特殊/其他/未知）。

示例：

```text
/moneylog recent 南瓜     # 查看"南瓜"最近变动
/moneylog recent 南瓜 转账  # 只看他的转账记录
/moneylog summary 南瓜     # 各类别净额汇总
/moneylog export 南瓜      # 导出他的全部流水为 CSV
```

CSV 导出位置：`plugins/MoneyLedger/export/ledger_<玩家>_<时间戳>.csv`，列：
`时间,玩家,类别,原因,来源,变动额,旧余额,新余额`。

## 三、类别是怎么分出来的

| 类别 | 判定依据 |
|---|---|
| **转账** | EssentialsX 事件原因 = 玩家 /pay |
| **活动/管理** | 事件原因 = /eco（eco give/take，含 PumpkinMail 经 eco 发奖） |
| **买卖** | 经 Vault + 调用栈来源 `com.economyshop` |
| **拍卖** | 来源 `com.auctionhouse` |
| **周税** | 来源 `com.skyblockexp.eztax` |
| **任务** | 来源 `com.leonardobishop.quests` |
| **每日收购** | 来源 `com.hh.dailysell` |
| **活动参与** | 来源 `com.nangua.buildrate`（建筑评分结算发奖） |
| 其他/未知 | 来源不在上表 / 原因无法识别 |

转账和 /eco（任务、活动发奖都走它）由 EssentialsX 自己精确标记；商店/拍卖/税/收购/任务/建筑评分这类"别的插件经 Vault 调"的，用**调用栈识别是哪个插件**归的类。

> **来源识别修复（2026-10-04）**：`detectSource` 原只取前两段包名（如 `com.nangua`），导致 `com.skyblockexp.eztax`、`com.leonardobishop.quests`、`com.hh.dailysell` 三段包名的映射实际失效；现改为返回完整包名（去掉类名），上述**买卖/周税/任务/收购**分类也一并修正生效，并新增 **「活动参与」**（BuildRate）类别。

## 四、已知边界（诚实说明）

- **只记在线期间的变动**：EssentialsX 余额变动事件需要玩家在线对象；给**离线**玩家发钱（如活动发奖给不在线的人）可能不进账本，建议发奖时玩家在线或发完上线后核对。
- **API 类别的准确度取决于调用栈**：如果某经济插件没在"来源表"里，会落到"其他"，可在源码 `SourceDetector.fromSource` 里加一行包名映射后重新打包。
- **不做账本修正**：只记录、不增删改别人余额，纯只读审计。
