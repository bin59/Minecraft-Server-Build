# EnchantShop —— 附魔商店（自研）

> 让玩家（尤其基岩版）用经验等级在箱子 GUI 里给手持装备买 ExcellentEnchants 自定义附魔，绕过物理铁砧。

## 为什么做这个

Geyser 把 Java 铁砧翻译成基岩铁砧后有两个老大难：

- **结果槽取物不可靠**：基岩玩家点铁砧结果槽经常取不到成品；
- **改名框映射错乱**：基岩端文字输入和 Java 铁砧改名框对不齐，搞乱整个交互。

Java 玩家蹲物理铁砧正常，基岩玩家附魔不顺。本插件用箱子 GUI（Geyser 对箱子菜单翻译很稳）替代物理铁砧。

## 玩家用法

1. 点快捷菜单 →「附魔商店」（或输入 `/eshop`）；
2. 把要附魔的装备**放进上方中间格子**（输入格）；
3. 下方列出全部已启用的自定义附魔，每个标注类型和价格（经验等级）；
4. 点一个附魔，按代码顺序过 6 道校验（`onClick`，任一不过就返回对应提示）：
   - Shift 点击 → **直接忽略**（不处理，也不给装备）；
   - 输入格没放装备 → 「请先把要附魔的装备放进上方中间格子」；
   - 装备类型不在该附魔的 `SupportedItems` 内（比如给剑买头盔附魔）→ 「不能用在 <材质> 上」；
   - 当前经验等级 < 该附魔价格 → 「经验等级不够！需要 N 级，你只有 M 级」（**先查等级再扣**，不会出现扣了钱没附魔）；
   - 已有该附魔且**等级已达 `Definition.MaxLevel`** → 「已满级（X 级）」；
   - 通过 → 扣 `AnvilCost` 级经验，把该附魔**升到 cur+1 级**写回输入格装备，并提示「已花费 N 级经验，<附魔> M 级（<材质>）」；
5. 关闭菜单时输入格的装备自动回到背包；**背包放不下会掉在脚边**（`addItem` 的 leftover 逐个 `dropItemNaturally`），不会凭空消失。

> **重要：这不是「一件装备只能买一次」的商店。** 同一附魔可以反复购买**逐级升高**（1 级 → 2 级 → …），每升一级都按同一个 `AnvilCost` 再扣一次经验等级，直到该附魔的 `Definition.MaxLevel` 才拒绝。只有满级才拦截，其余每次都扣费——这点与旧版本文档「已有该附魔 → 提示不重复扣」的描述相反，已按源码纠正（火焰行者 boots 满级 2，意味着同一双靴子最多花 2×7=14 级经验）。

## 扣费与施加逻辑

- **价格来源**：读该附魔在 `plugins/ExcellentEnchants/enchants/<id>.yml` 里的 `AnvilCost`（注意源码用的是**相对路径** `plugins/ExcellentEnchants/enchants`，即相对服务端进程的**工作目录**，不是相对 jar 所在目录）；没配 `AnvilCost` 时落到本插件的 `default-cost`（默认 3 级）；
- **扣的是经验等级条**：`player.giveExpLevels(-cost)`，和铁砧手感一致；**升级续购按同一价再扣一次**，不是首级免费；
- **施加**：从运行时注册表取 `excellentenchants` 命名空间附魔，读出当前等级 `cur`（`meta.getEnchantLevel`，无则 0），再以 `meta.addEnchant(en.enchant, cur + 1, true)` 写回——第三参 `true` 即 **ignoreLevelRequirement**，绕过原版"经验等级要够"的装备等级限制（这正是本插件存在的意义之一）；
- **满级拦截**：`cur >= Definition.MaxLevel`（默认 1）才拒绝，界面同时把 `MaxLevel` 显示成「满级 N」；
- **装备类型校验**：读各附魔 `SupportedItems`（`helmet` / `swords_axes` / `bow_crossbow` / `boots` 等，缺省 `any`），按物品材质类别判断能否施加，不符则拒绝；
- **不依赖主手**：用独立输入格，避免快捷菜单触发物（时钟）占着手时误把时钟当装备；
- **GUI 顶部其它格子**一律 `setCancelled(true)`，Shift 点击直接 return，防止把附魔图标取走或错位触发。

## 配置

`plugins/EnchantShop/config.yml`：

```yaml
# 当某附魔配置里没有 AnvilCost 时的默认价格（经验等级）
default-cost: 3
```

## 显示名与附魔列表

- 列表来自**运行时注册表**：遍历 Bukkit 附魔注册表，筛 `excellentenchants` 命名空间——线上 EE 启用几个就列几个，不看磁盘目录；
- 显示名读各附魔 yml 的 `Definition.DisplayName`（自动剥掉 MiniMessage 颜色标签）；
- 配置文件查找顺序：先 `plugins/ExcellentEnchants/enchants/<id>.yml`，找不到再找 `_disabled_/<id>.yml`。

**新增附魔**：在 EE 里启用（把 `_disabled_/` 下对应 yml 移回 `enchants/`），重启后自动出现在商店，价格自动读 `AnvilCost`，无需改本插件。

**本服实例（2026-11-14）**：`flame_walker`（火焰行者）已启用，是**仅能在本商店购买**的附魔——EE 侧 `Tradeable` / `On_Random_Loot` 等产出开关已全部关掉，不会出现在附魔台、箱子、钓鱼、村民交易。商店显示「火焰行者 / 类型 boots · 满级 2 / 每升一级 7 级经验」。配置见 [`ExcellentEnchants自定义附魔.md`](../../3-玩法与玩家功能插件/自定义附魔-ExcellentEnchants/ExcellentEnchants自定义附魔.md) 的「只售卖附魔的产出隔离」。

## 构建

**依赖极简**：本插件只用 Bukkit API 读 ExcellentEnchants 的**磁盘配置文件**，不调用 EE 的 Java API，所以编译期不需要 EE 的 jar 参与类型解析（`pom.xml` 里 EE 是 `provided` 且注释写明"仅以 Bukkit API 读取其磁盘配置"）。运行期 `depend: [ExcellentEnchants]` 才是硬要求——EE 没加载，本插件不会启动。

按仓库总则（JDK 25 + `--release 21`），手工编译：

```bash
javac --release 21 -encoding UTF-8 -d out \
  -cp "自研/lib/leaf-api-26.3.build.13-alpha.jar;<adventure-api 5.2.0>;<annotations 23.0.0>" \
  src/main/java/com/nangua/enchshop/EnchantShop.java
# 再把 src/main/resources/{plugin.yml,config.yml} 与 out/ 一起打包成 target/EnchantShop-1.0.0.jar
```

或直接用 `pom.xml`（`maven.compiler.release=21`、`finalName=${artifactId}-${version}` → `EnchantShop-1.0.0.jar`）。旧版本文档写的"用 JDK 21 编译"表述不准：leaf-api 是 Java 25 字节码，**低版本 JDK 的 javac 读不了它**，必须用 JDK 25 并加 `--release 21` 才能既编译成功又产出 Java 21 字节码。
