# ClickMobsLogger · 使用说明

> 自研审计插件：记录**玩家用 ClickMobs 把动物收成头颅**的行为，落盘为 `plugins/ClickMobsLogger/pickups.jsonl`（每行一条 JSON），`/cml` 可查最近记录。不改动 ClickMobs、不给物品、不影响拾取流程，纯旁路记录。

| 项 | 值 |
| --- | --- |
| 版本 / 主类 | `1.0.0` / `com.pumpkin.cml.ClickMobsLogger` |
| 源码 | `自研/ClickMobsLogger/src/com/pumpkin/cml/`（`ClickMobsLogger.java`、`PickupListener.java`） |
| 资源 | `自研/ClickMobsLogger/resources/`（`plugin.yml`、`config.yml`） |
| 成品 jar | `自研/ClickMobsLogger-1.0.0.jar`（在 `自研/` 根目录，不在 `target/`） |
| jar md5 | `092abcb4d8e287461c1c6e07e0773606` |
| `api-version` | `1.21`（其它自研插件为 `26.3`） |
| 字节码 | class major **69**（JDK 25 默认编译，未加 `--release 21`） |
| 运行时依赖 | 仅 Bukkit API；功能上依赖 ClickMobs（未声明 `softdepend`，缺它也能启动，只是永不产生记录） |
| 命令 / 权限 | `/cml [玩家名]` / `clickmobslogger.use`（`default: op`） |
| 数据文件 | `plugins/ClickMobsLogger/pickups.jsonl`、`plugins/ClickMobsLogger/config.yml` |

**2026-11-15 核对**：本地 26.3 主服 `plugins/` 内没有该 jar，也没有 `ClickMobsLogger/` 数据目录；下列部署与验证步骤以仓库内源码/产物为准，插件尚未在实服运行过。

## 1. 判定原理（为什么不用权限判断）

反编译本服实跑的 `ClickMobs-paper-1.3.1.jar` → `de.clickism.clickmobs.mob.PickupManager#onInteract`，一次成功的收纳是**同步**完成的：

```text
PlayerInteractEntityEvent（主手）
  → isSneaking() / 手持物品黑名单 / canPickUp()（白黑名单 + clickmobs.pickup 权限）
  → setCancelled(true)
  → toItemStack(entity) 内部 LivingEntity.remove()   ← 实体在这里被移除
  → Utils.setHandOrGive() 给头颅物品 + sendPickupEffect()
```

Logger 不判断 `clickmobs.pickup` 权限，只认「实体是否真的消失」：

```java
@EventHandler  // 默认优先级、ignoreCancelled=false，事件被 ClickMobs 取消也照样收到
public void onInteract(PlayerInteractEntityEvent e) {
    if (e.getHand() != EquipmentSlot.HAND) return;
    Entity ent = e.getRightClicked();
    if (!(ent instanceof Animals)) return;
    Player p = e.getPlayer();
    if (!p.isSneaking()) return;
    String type = ent.getType().name();
    if (!plugin.isTracked(type)) return;
    if (plugin.isHandBlacklisted(p.getInventory().getItemInMainHand().getType())) return;

    Location loc = ent.getLocation().clone();
    Entity ref = ent;
    Bukkit.getScheduler().runTaskLater(plugin, () -> {
        if (ref.isValid() && !ref.isDead()) return;  // 还在 = 没收走，不记
        plugin.logPickup(p, type, loc);
    }, 1L);
}
```

这样天然过滤掉「没权限 / 白名单外 / 黑名单生物 / 手持黑名单物品 / 创造模式不允许」等所有被 ClickMobs 拒绝的点击——它们都不会移除实体。

> `tracked-mobs` 与 `blacklist-items-in-hand` 只是**前置过滤优化**，不是准确性的来源：
> - 黑名单漏填 → 不会误记，只是多跑一次 1-tick 检查；
> - `tracked-mobs` 填窄 → **会漏记**（记录被前置过滤掉，实体消失也救不回来）。

## 2. 部署

1. 把 `自研/ClickMobsLogger-1.0.0.jar` 复制到服务端 `plugins/`。
2. **停服后完整重启**，不要用 `/reload` 换 jar（参见 `自研/README.md` §四）。
3. 首次启动生成 `plugins/ClickMobsLogger/config.yml` 与空的 `pickups.jsonl`，启动日志会打印记录文件绝对路径。
4. 权限：本服 LuckPerms 为显式授权模式，管理员要给 `clickmobslogger.use`；op 默认已有。

```mcfunction
/lp group admin permission set clickmobslogger.use true
```

**没有 reload 命令**：改 `config.yml` 后必须重启服务端才生效。

## 3. 配置

`plugins/ClickMobsLogger/config.yml`（首次启动从 jar 内导出）：

```yaml
tracked-mobs:
  - ALL
blacklist-items-in-hand:
  - LEAD
  - SADDLE
```

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `tracked-mobs` | `[ALL]` | 要记录的 `EntityType` 名，大小写不敏感；含 `ALL` 则记录所有 `Animals`。**只在 `Animals` 范围内生效**，见 §6。留空时代码回退 `[COW, PIG, SHEEP]` |
| `blacklist-items-in-hand` | `[LEAD, SADDLE]` | 主手拿这些材料时跳过记录；留空回退同值。仅作过滤优化，见 §1 |

**与 ClickMobs 实跑配置的对照**（`plugins/ClickMobs/config.yml`）：

| ClickMobs 键 | 本服现值 | 对 Logger 的影响 |
| --- | --- | --- |
| `whitelisted_mobs` | `[cow, pig, sheep]` | 只有这三种动物真会被收走；三者都是 `Animals`，当前 `ALL` 能完整覆盖 |
| `blacklisted_mobs` | `[?hostile, wither, ender_dragon]` | 敌对生物不可捡，Logger 也不会记 |
| `blacklisted_items_in_hand` | `[lead, saddle]` | 与 Logger 的黑名单一致；改了这边要同步改 Logger（不改也不会误记） |
| `per_mob_permissions` | `false` | 只校验 `clickmobs.pickup`；Logger 靠实体消失判定，无需同步 |
| `enable_dispensers` | `true` | 发射器生成的生物不经玩家交互，Logger 不记，见 §6 |

> ClickMobs 还隐含阻止 harness 类物品（Happy Ghast 兼容），不需要写进配置；Logger 同样靠实体消失过滤，不受影响。

## 4. 日志格式

`plugins/ClickMobsLogger/pickups.jsonl`，**每行一条完整 JSON**（JSONL），追加写、无表头：

```json
{"time":"2026-11-15 05:12:03","player":"Notch","uuid":"069a79f4-44e9-4726-a5be-fca90e38aaf5","entity":"COW","world":"world","x":128.50,"y":64.00,"z":-302.31}
```

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `time` | `LocalDateTime.now()` | `yyyy-MM-dd HH:mm:ss`，**服务器系统本地时间、不带时区** |
| `player` | `Player.getName()` | 写入时转义 `\` 与 `"` |
| `uuid` | `Player.getUniqueId()` | 基岩玩家为 Floodgate UUID；可用于跨改名对账 |
| `entity` | `EntityType.name()` | 大写，如 `COW` |
| `world` | `Location.getWorld().getName()` | 世界名为 null 时写 `?` |
| `x` / `y` / `z` | 实体被移除前 `clone()` 的坐标 | `%.2f`，保留两位小数 |

解析示例（无需额外依赖）：

```bash
# 最近 10 条
tail -n 10 plugins/ClickMobsLogger/pickups.jsonl

# 按玩家统计（jq）
jq -r '.player' plugins/ClickMobsLogger/pickups.jsonl | sort | uniq -c | sort -rn
```

```python
import json, io
with io.open('plugins/ClickMobsLogger/pickups.jsonl', encoding='utf-8') as f:
    rows = [json.loads(line) for line in f if line.strip()]
print(len(rows), '条记录')
```

## 5. 命令

| 命令 | 作用 |
| --- | --- |
| `/cml` | 倒序显示最近 20 条记录 |
| `/cml <玩家名>` | 倒序显示该玩家最近 20 条匹配记录 |

实现细节（`ClickMobsLogger#onCommand`）：

- 过滤用精确子串 `"player":"<玩家名>"`，**大小写敏感**、不支持模糊匹配 / 多条件 / 时间段；多余参数被忽略。
- `limit` 固定 20，代码内常量，不可配置。标题写「最近 20 条」，传玩家名时实际含义是「最近 20 条**匹配**记录」。
- `Files.readAllLines()` 全量读入内存并倒序，在**主线程**执行；记录文件变大后会卡顿，见 §6。
- 文件不存在时提示「没有记录文件」；无匹配时提示「无匹配记录」。
- 需要 `clickmobslogger.use`，否则提示「你没有权限使用此命令」。

## 6. 已知限制

| # | 限制 | 影响 / 处理 |
| --- | --- | --- |
| 1 | 只记录 `org.bukkit.entity.Animals` 子类 | 若将来把 ClickMobs 白名单放宽到村民、恶魂、Happy Ghast 等**非 Animals** 生物，Logger 会漏记；当前白名单 `cow/pig/sheep` 全在范围内，现状无漏记 |
| 2 | 只监听主手 `PlayerInteractEntityEvent` | 副手交互、ClickMobs 的 `VehicleInteractListener`（船/矿车）、`DispenserListener`（发射器，本服 `enable_dispensers: true`）产生的实体变动都不记录 |
| 3 | 1-tick 判据是「实体失效」而非「确由 ClickMobs 移除」 | 同一 tick 内实体被其它插件 / 玩家击杀 / 清理，可能被**误记**为拾取；高频场景需人工核对 |
| 4 | 基岩（Geyser）交互未实跑验证 | 本服玩家以基岩为主，Geyser 转译的右键 / 潜行事件是否稳定触发 `PlayerInteractEntityEvent(HAND)` 需上线后实测 |
| 5 | 日志无轮转、无上限、无清理 | `pickups.jsonl` 会无限增长；`/cml` 全量读文件、每条记录一次 `FileWriter` 同步 I/O（主线程 + `synchronized`），量大后要手动归档或改异步批量写 |
| 6 | 时间无时区标记 | 换服务器时区 / 跨机合并日志对账时先统一时间基准 |
| 7 | `api-version: 1.21` 与 26.3 服务端不一致 | 未在实服验证加载；与其它自研插件口径不同，升级时留意 |
| 8 | 日志含玩家名、UUID、精确坐标 | 属玩家数据，不外传；归档时按数据管理约定处理 |

**漏记排查顺序**：① 玩家是否 shift + 主手右键；② `tracked-mobs` 是否把该类型排除；③ ClickMobs 是否真的移除了实体（权限 / 白黑名单 / 创造模式）；④ 实体是否属于 `Animals`；⑤ 主服 `plugins/ClickMobsLogger/` 是否可写、启动日志有无「写入日志失败」。

## 7. 构建（2026-11-15 实测）

本插件**没有 `pom.xml` / `build.py` / `target/`**，只依赖 Bukkit API。用 JDK 25 编译，classpath 需 6 个 jar（leaf-api 不带传递依赖）：

| 用途 | jar |
| --- | --- |
| 服务端 API | `自研/lib/leaf-api-26.3.build.13-alpha.jar` |
| 传递依赖 | `libraries/net/kyori/adventure-api/5.2.0/adventure-api-5.2.0.jar` |
| 同上 | `libraries/net/kyori/adventure-key/5.2.0/adventure-key-5.2.0.jar` |
| 同上 | `libraries/org/jetbrains/annotations/24.1.0/annotations-24.1.0.jar` |
| 同上 | `libraries/com/google/guava/guava/33.6.0-jre/guava-33.6.0-jre.jar` |
| 同上 | `libraries/net/md-5/bungeecord-chat/1.21-R0.2-deprecated+build.21/bungeecord-chat-1.21-R0.2-deprecated+build.21.jar` |

在项目根目录 `Minecraft-Server-Build/` 下执行；`服务器数据备份/` 是它的**同级目录**，所以要带 `../`。Windows 下 classpath 分隔符是 `;`，在 Git Bash 里**必须整体加引号**。

```bash
ROOT="自研/ClickMobsLogger"
LIB="自研/lib/leaf-api-26.3.build.13-alpha.jar"
L="../服务器数据备份/leaf-26.3/leaf-26.3/libraries"
CP="$LIB;$L/net/kyori/adventure-api/5.2.0/adventure-api-5.2.0.jar;$L/net/kyori/adventure-key/5.2.0/adventure-key-5.2.0.jar;$L/org/jetbrains/annotations/24.1.0/annotations-24.1.0.jar;$L/com/google/guava/guava/33.6.0-jre/guava-33.6.0-jre.jar;$L/net/md-5/bungeecord-chat/1.21-R0.2-deprecated+build.21/bungeecord-chat-1.21-R0.2-deprecated+build.21.jar"

rm -rf "$ROOT/build" && mkdir -p "$ROOT/build/classes"
javac -encoding UTF-8 -d "$ROOT/build/classes" -cp "$CP" $(find "$ROOT/src" -name '*.java')
cp "$ROOT/resources/plugin.yml" "$ROOT/resources/config.yml" "$ROOT/build/classes/"
(cd "$ROOT/build/classes" && jar --create --file ../../../ClickMobsLogger-1.0.0.jar .)
```

`../../../` 从 `自研/ClickMobsLogger/build/classes/` 回到 `自研/`，即现有 jar 所在位置。重编会覆盖 `自研/ClickMobsLogger-1.0.0.jar`，按项目习惯先把旧 jar 改名 `.bak-YYYYMMDD` 再执行。

**实测结果**（JDK `25.0.5.0.3+1-LTS-2`）：

| 方式 | 产物 class major | 能否编译 |
| --- | --- | --- |
| `javac`（默认，与现有 jar 一致） | 69 = Java 25 | ✅ |
| `javac --release 21` | 65 = Java 21 | ✅ |

两种方式的 class 大小相同（`7271` / `3035` 字节）。按默认方式重编译 + 重打包后，两个 class、`plugin.yml`、`config.yml`、`MANIFEST.MF` 与仓库内 `ClickMobsLogger-1.0.0.jar` **逐字节一致**，确认 jar 与源码完全同步、未被改过。

> 现有 jar 是 Java 25 字节码：本服 `logs/latest.log` 实跑 `Running Java 25`，可加载 major 69；若把服务端换回 Java 21，需按 `--release 21` 重编，否则 `UnsupportedClassVersionError`。

md5sum 自研/ClickMobsLogger-1.0.0.jar                  # 092abcb4...
unzip -p 自研/ClickMobsLogger-1.0.0.jar plugin.yml
javap -verbose -classpath 自研/ClickMobsLogger-1.0.0.jar com.pumpkin.cml.ClickMobsLogger | grep "major version"   # 69

部署后核对：`grep -n "ClickMobsLogger 已启用" logs/latest.log`、`ls -l plugins/ClickMobsLogger/pickups.jsonl`、shift+右键收一只牛后 `cat plugins/ClickMobsLogger/pickups.jsonl`。
