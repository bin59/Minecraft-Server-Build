# OfflineReward 在线/离线奖励 · 使用说明

> 对应 Leaf 26.3 实跑服，当前版本 `1.1.4`。源码、配置与 jar 均在 `自研/在线离线奖励-OfflineReward/`。`api-version: 26.3`，class major 65（Java 21 目标）。奖励通过 **PumpkinMail（南瓜邮箱）** 发放，玩家输入 `/mailbox` 领取。

本插件按「在线时长」和「离线时长」两条线分别发南瓜币到邮箱：

- **离线奖励**：玩家下线后，按离线时长一次性补发（15 币/小时，1 小时起算）。
- **在线奖励**：玩家在线时按「今日累计在线时长」分 8 个阶段逐档发放，奖励一次比一次多，**全天最多 300 币，累计 3 小时毕业**。

1.1.4 起新增 **AFK 门控**：挂机（EssentialsX 判定为 AFK）的时段**不计在线时长、不发在线奖励**——这是本说明的重点，见 §4。

---

## 一、奖励规则速览

| 项目 | 离线奖励 | 在线奖励（stages，默认） |
| ---- | ---- | ---- |
| 触发 | 玩家上线时结算上次离线时长 | 在线期间每分钟 tick 判定，达标即发 |
| 计价 | 15 币/小时，1 小时起算 | 8 档固定币数，合计 300 币 |
| 上限 | 单次最多计 24 小时、冷却 0 小时 | 全天封顶 300 币（`max-per-day: 300`） |
| 毕业 | 无 | 累计在线 3 小时（180 分）领满 8 档后当天不再发 |
| 累计 | 每次离线独立算 | 当日内分次上线可累计，跨天自动重置 |
| AFK 门控 | ❌ 不受影响（下线时长与挂机无关） | ✅ 1.1.4 起挂机时段剔除 |

---

## 二、离线奖励

- **15 币/小时**（`reward.coins-per-hour: 15`）。
- **不足 1 小时不发**（`min-hours: 1`）；`floor-minutes: true` 表示不足整小时的分钟舍去，按整小时计。
- **单次最多计 24 小时**（`max-hours-per-day: 24`），防长期不上线刷爆。
- **冷却 0 小时**（`cooldown-hours: 0`），不限制反复上下线（在线奖励那侧另有每日封顶）。
- 发放后进邮箱，聊天提示（可用 `announce: false` 关闭）。

---

## 三、在线奖励（阶段发放，1.1.3 起）

按当日累计在线时长达到各阶段时间点时逐档发放，间隔 **5 → 10 → 15 → 之后每 30 分钟**一档：

| 档位 | 累计在线 | 本档间隔 | 发放 | 累计发放 |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 5 分 | 5 分 | 10 币 | 10 |
| 2 | 15 分 | 10 分 | 15 币 | 25 |
| 3 | 30 分 | 15 分 | 20 币 | 45 |
| 4 | 60 分 | 30 分 | 25 币 | 70 |
| 5 | 90 分 | 30 分 | 30 币 | 100 |
| 6 | 120 分 | 30 分 | 40 币 | 140 |
| 7 | 150 分 | 30 分 | 60 币 | 200 |
| 8 | 180 分（3 小时） | 30 分 | 100 币 | **300（毕业）** |

- **全天最多 300 币**：阶段表合计恰好 300，再用 `max-per-day: 300` 做硬封顶；领满 8 档当天毕业，不再发放。
- **分次上线可累计**：当日内多次上线的在线时长累加，跨天自动重置（在线累计、阶段进度、日期标记一并清）。
- **阶段表全在 config**：`online-reward.stages` 的 `minutes` / `coins` 可改，改完 `/offlinereward reload` 即生效，无需重新编译。想改金额时别让合计超过 300，否则末档会被 `max-per-day` 截断。

### 循环模式（mode: cycle，可回退 1.1.2 行为）

`mode: cycle` 时按 `cycle-minutes: [10, 20, 30]` 序列循环结算，25 币/小时按真实在线毫秒精确计价（`min-minutes: 5` 起算）。1.1.4 的 AFK 门控对两种模式都生效。

## 四、AFK 门控（1.1.4 新增，重点）

**挂机不算在线时长、不发在线奖励。** 通过**反射**接入 EssentialsX 的 `Essentials.getUser(Player).isAfk()`，编译期零硬依赖（不 import 任何 Essentials 类）。

### 4.1 门控行为

| 环节 | 行为 |
| ---- | ---- |
| 判定方式 | 反射调用 EssentialsX `UserData.isAfk()`；Method 缓存到 static，每次调用开销极小 |
| 定时 tick | 每分钟发现玩家 AFK → 把计时锚点 `lastLogin` 推进到当前时刻，**丢弃该段、不累计、不发奖**；恢复活跃后从新锚点重新累计 |
| 退出结算 | 退出时若 AFK → 跳过最后一段结算；非 AFK 才正常结算 |
| 循环模式 | AFK 期间越过结算点也不补发，顺延下次结算 |
| 降级 | EssentialsX 未装 / 版本不匹配 / 反射异常 → 自动视为「非 AFK」，照常计时，**绝不让在线奖励因此停摆** |
| 开关 | `online-reward.ignore-afk: true`（默认），设 `false` 关闭门控；`/offlinereward reload` 即生效 |
| 可观测 | 启动日志与 `/offlinereward check <玩家>` 显示门控状态（开 / 关 / API 未接入 / AFK / 活跃） |
| 范围 | **只影响在线奖励**；离线奖励（下线时长）与豁免玩家不受门控影响 |

### 4.2 ⚠️ 判定门槛：两个 Essentials 配置项别搞混

门控读的是 `isAfk()`，而玩家何时被标记为 AFK **由 EssentialsX 的 `auto-afk` 决定**，不是踢出配置。本服实测（`leaf-26.3-多服/plugins/Essentials/config.yml`）：

| Essentials 配置项 | 本服值 | 作用 | 与门控关系 |
| ---- | ---- | ---- | ---- |
| `auto-afk` | **300 秒（5 分钟）** | 无操作多久**标记为 AFK**（`isAfk()` 变 true 的来源） | ✅ 决定门控何时生效 |
| `auto-afk-timeout` | **-1** | 标记 AFK 后多久**踢人/执行命令**（-1 = 不踢） | ❌ 无关，纯踢人开关 |

**结论**：

- 挂机满 **5 分钟**才被标记 AFK，这 5 分钟**仍会计入**在线时长（ Essentials 的标记延迟）；AFK 判定是每分钟 tick 粒度，非秒级。
- 想让门槛更严（更早停计），要调 EssentialsX 的 `auto-afk`（那属于运行服配置改动，本插件不动）。
- 本服 `auto-afk-timeout: -1`（不踢人）——这反而有利：挂机者不会被踢下线转成「离线奖励」继续薅，但在线时长照扣，两头都堵。

### 4.3 与 Plan 的 AFK 区别

Plan 插件另有 `Data_gathering.AFK_threshold: 3 MINUTES`，那是**第三套独立机制**，只用于会话 `afk_time` 统计（在线时间排行 PlanTop 的活跃排行 = 会话时长减 AFK），**不参与奖励发放**。别与 EssentialsX 这套混淆。

## 五、豁免与权限

- **豁免节点 `offlinereward.exempt`**：显式设为 `true` 的玩家**不发**在线 + 离线奖励（用于测试号 / 特殊账号）。
- 1.1.1 起豁免只认「显式赋权」的精确节点，admin 组的 `*` 通配**不再误伤**——管理员（含 OP）默认**照常领取**奖励。
- 设置命令：`lp user/group <名字> permission set offlinereward.exempt true`

---

## 六、命令与权限

| 命令 | 作用 | 权限 |
| ---- | ---- | ---- |
| `/offlinereward reload`（别名 `/offr`） | 重载配置（阶段表 / ignore-afk 开关即时生效） | `offlinereward.admin`（默认 op） |
| `/offlinereward check <玩家>` | 查看该玩家豁免状态、今日已发、在线起点、AFK 门控状态 | `offlinereward.admin`（默认 op） |

## 七、配置速查（`config.yml`）

```yaml
reward:
  coins-per-hour: 15        # 离线每金币
  min-hours: 1              # 离线不足 1 小时不发
  max-hours-per-day: 24     # 单次最多计 24 小时
  floor-minutes: true       # 不足整小时舍去
announce: true              # 发放聊天提示
db: offline.db              # 数据文件（plugins/OfflineReward/ 下）
exempt-permission: offlinereward.exempt

online-reward:
  enabled: true
  mode: stages              # stages（默认） | cycle（回退 1.1.2）
  ignore-afk: true          # 1.1.4：AFK 不计在线时长，false 关闭
  stages:                   # 累计 minutes 分钟 → 发 coins 币
    - {minutes: 5,   coins: 10}
    - {minutes: 15,  coins: 15}
    - {minutes: 30,  coins: 20}
    - {minutes: 60,  coins: 25}
    - {minutes: 90,  coins: 30}
    - {minutes: 120, coins: 40}
    - {minutes: 150, coins: 60}
    - {minutes: 180, coins: 100}
  max-per-day: 300          # 全天在线奖励硬封顶
```

> 配置文件在 `src/main/resources`、`target/classes`、jar 内三处字节一致。服务器实跑 config 需服主手动覆盖（升级时尤其注意 `ignore-afk` 与 `stages` 要写进去，`saveDefaultConfig()` 不会覆盖已有 config）。

## 八、依赖与部署

- **PumpkinMail**（softdepend）：奖励发放到南瓜邮箱，未装则发不出去。
- **Vault**（softdepend）：经济接口。
- **EssentialsX**（softdepend，1.1.4 AFK 判定）：缺失时门控自动降级为非 AFK，插件照常运行。
- **构建**：`python build.py` 离线编译，产物 `OfflineReward-1.1.4.jar`（约 11.98 MB，含 sqlite-jdbc，自包含）。AFK 门控走反射，编译期无需 `lib/EssentialsX.jar`；该 jar 仅用于本地核对 API 签名。
- **升级部署**：停服 → 旧 jar 改名 `.bak-日期` → 放 1.1.4 jar → 覆盖 `config.yml`（补 `ignore-afk`、`stages`）→ **完整重启**（不要 `/reload`）。
