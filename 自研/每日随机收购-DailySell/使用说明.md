# DailySell 每日随机收购 · 使用说明

> 对应 Leaf 26.3 实跑服，版本 `1.2.3`。源码、配置与 jar 均在 `自研/每日随机收购-DailySell/`；实跑副本在 `服务器数据备份/leaf-26.3/leaf-26.3/plugins/`。

每天从 **110 种物品池**里随机抽 **8 种**作为全服共享的今日候选，每位玩家**自选 5 种**作为自己当天唯一能出售的清单。单价当日浮动、每种额度随机，单人每日总收益封顶 800 南瓜币。基岩玩家 `/ds` 直接弹**原生表单**自选与出售，全程无需打字。

---

## 一、玩法概览

| 环节 | 规则 |
| ---- | ---- |
| 物品池 | `config.yml` 的 `pool`，110 种，基础价 1~20 币（作物 / 食物 / 肉类 / 矿物 / 原木 / 怪物掉落 / 海洋 / 花草 / 羊毛 / 杂项） |
| 今日候选 | 每天零点抽 8 种，**全服共享**；同一天重启不会重抽，`daily.yml` 保存清单、单价与额度 |
| 单价 | `基础价 × [0.6, 1.4)` 四舍五入，最低 1 币 |
| 每种额度 | 10~60 个随机（`min-per-item` / `max-per-item`）；生成时若 8 种合计金额超过 900 币会自动缩减额度 |
| 自选 | 每人从 8 种里选 5 种，**未选满不能出售**；选择按日期持久化，重登 / 重启不变，跨天自动失效 |
| 收益上限 | `daily-budget: 900`，既是清单总价上限，也是**每人每日总收益上限**；按「玩家 + 日期」独立累计，重选清单不会重置 |
| 双端 | Java 端 27 格箱子 GUI（自选界面 + 收购界面）；基岩端 `/ds` 直接弹**原生表单**：CustomForm 开关自选 5 种 + SimpleForm 逐项一键出售，无需输入任何命令 |

> 与旧版的区别：旧版每天固定 4 种、全服共用且无需选择；现在 8 种候选里每人挑 5 种，玩家可按自己手里的资源决定卖什么。

## 二、部署

1. 停服，**先删掉旧的 `DailySell-1.2.x.jar`**（避免新旧 jar 同时被加载），再把 `DailySell-1.2.3.jar` 放入 `plugins/`，**完整重启**，不要用 `/reload`。
2. 前置：`Vault` + 经济提供器（EssentialsX）。plugin.yml 里 `softdepend: [Vault]`，但 `onEnable()` 找不到经济提供器会直接禁用插件。
3. 首次启动生成 `plugins/DailySell/config.yml`、`daily.yml`、`data.yml`。
4. **升级最关键的一步：必须把本项目的 `src/main/resources/config.yml`（`items-per-day: 8`、`choices-per-day: 5`）覆盖到服务器 `plugins/DailySell/config.yml`**（先备份旧的）。`saveDefaultConfig()` 不会覆盖服务器已有 config，若只换 jar 不换 config，插件仍按旧值生成清单——这正是「每日收购还是只有 4 个」的头号原因。配置在 `src/main/resources`、`target/classes`、项目根副本、jar 内 4 处字节一致，服务器实跑 config 需你手动覆盖。
5. 验证：`/ds today` 应显示 8 种候选与序号；选满 5 种后 `/ds sell` 手持对应物品应扣物品并到账。

> ⚠️ **升级后当天清单怎么变成 8 种**：旧版每天固定 4 种、无需选择；现版 8 选 5。1.2.3 起插件检测到 `daily.yml` 里已存清单数量 < 当前 `items-per-day`（旧版小清单残留），会在**启动时自动重抽**为本日 8 种候选，无需管理员手动 `/ds reroll`（已用 `autoUpgraded` 按天标记，不会每分钟反复重抽）。但若 `config.yml` 还是旧的 `items-per-day: 4`，重抽也只会生成 4 种——所以**覆盖 config 是前提**。

插件元数据：`api-version: 26.3`，class major 65（Java 21），3 个 class；源码单文件 `src/main/java/com/hh/dailysell/DailySell.java`。

## 三、命令

主命令 `/ds`，权限 `dailysell.use`（默认全体玩家）；管理命令需 `dailysell.admin`（默认 op）。

| 命令 | 说明 | 可用端 |
| ---- | ---- | ------ |
| `/ds` / `/ds gui` / `/ds menu` | 未选满时打开**自选界面**，选满后打开**收购界面** | Java |
| `/ds choose [1-8\|clear]` | 不带参数打开自选界面；带序号选 / 取消第 N 种；`clear` 清空当天选择 | 双端 |
| `/ds today` | 列出 8 种候选、序号、单价、额度、`✔` 已选、我已卖数量与今日已赚金额 | 双端 / 控制台 |
| `/ds sell` | 手持物品卖 1 个 | 双端 |
| `/ds sellall` | 手持那一组物品卖到「剩余额度 / 剩余预算」上限 | 双端 |
| `/ds reload` | 重载 `config.yml`（今日清单不变） | 控制台 / 管理员 |
| `/ds reroll` | 重新生成今日清单（清空当天自选、关闭过期 GUI） | 控制台 / 管理员 |

常用示例：

```
/ds today                 # 看今天 8 种候选和序号
/ds choose 1              # 选第 1 种
/ds choose 3
/ds choose 7
/ds choose clear          # 选错了清空重来（已卖额度与已赚金额不重置）
/ds sellall               # 手持选中的物品批量出售
```

> `/ds sellall` 只按**手持那一组**的数量计算上限；背包里另有同种物品想一起卖，用 GUI 的 Shift+左键（会统计整个背包）。

## 四、自选界面与基岩原生表单

### Java 端（箱子 GUI）

`/ds` 在**未选满 5 种**时打开 27 格自选界面，选满后点「确认」直接进入收购界面。

| Slot | 内容 |
| ---- | ---- |
| 10~17 | 今日 8 种候选，点击切换选中 / 取消；已选中带附魔光效与 `✔` 标记 |
| 18 | 清空今日选择 |
| 22 | 统计：已选 N / 5、今日候选数、选择有效期 |
| 24 | 确认（未选满会提示还差几种）；选满后关闭并打开收购界面 |

收购界面按每页 14 个物品位分页展示**你选中的 5 种**（当前 5 种一页即可放完；slot 18 / 26 翻页），左键卖 1 个、Shift+左键卖满额度；额度用完的图标不再附魔。

> 插件只接管 GUI 顶栏：在界面里点击自己的背包 / 快捷栏会正常整理，不会被取消，也不会误触发选择或出售。关闭界面、退出游戏都会释放界面引用。

### 基岩端（原生表单，1.2.2 起）

基岩玩家执行 `/ds`（或 QuickMenu 菜单的「每日收购」按钮）时**不再打开箱子 GUI**，而是直接发 Floodgate 原生表单：

| 状态 | 表单 | 操作 |
| ---- | ---- | ---- |
| 未选满 5 种 | CustomForm「每日收购 · 自选 5 种」 | 每种候选一个开关（显示单价 / 额度 / 已卖数），打开恰好 5 个后点提交；数量不对会提示并重新弹出 |
| 已选满 | SimpleForm「每日收购 · 出售」 | 每种选中物品一个按钮（显示剩余额度与单价），点击把背包里该物品**一次卖到额度 / 预算上限**；卖完自动刷新表单继续卖；末尾「重新自选」按钮可清空重选 |

- 表单响应回调在 Netty 网络线程触发，插件内部全部切回主线程执行（与 QuickMenu 同一套模式）。
- 未安装 Floodgate 时自动回退箱子 GUI，Java 端行为完全不变；表单发送异常时兜底回 GUI。
- `/ds choose <序号>` 命令仍保留可用，但基岩玩家正常情况下不再需要打任何字。
- 防刷口径与 Java 端完全一致：`bedrockSell()` 同走 `剩余额度 / 剩余预算 / 持有量` 三者取最小、`recordSale()` 写 `__earned` 累计。

## 五、配置

`config.yml` 全部键与当前值：

```yaml
items-per-day: 8          # 今日候选种类
choices-per-day: 5        # 每人可自选种类（会被 items-per-day 限制）
min-per-item: 10          # 每种最低额度
max-per-item: 60          # 每种最高额度
price-float-min: 0.6      # 单价浮动下限
price-float-max: 1.4      # 单价浮动上限
daily-budget: 900         # 清单总价上限 = 每人每日收益上限
broadcast: true           # 零点 / reroll 时全服广播清单
pool:                     # 110 种 Material 名 : 基础价
  WHEAT: 2
  ...
```

调参提示：

- 每天 8 种、`max-per-item: 60` 是在 900 币预算下模拟 5000 次后选定的组合（额度上限 100 时约 15% 生成失败，60 时降到 0.04%）。**加大 `items-per-day` 或单价时记得同步降低 `max-per-item`**。
- 池里的键必须是 26.3 的合法 `Material` 名且 `isItem()` 为真；本次已修正旧键 `NETHER_QUARTZ` → `QUARTZ`（旧键在 26.3 一直抽不中）。GUI 中文名映射写在 Java 源码的 `ZH` 表里，新增池键必须同步补中文名，否则界面显示英文。
- 改 `pool` / 参数后 `/ds reload` 生效，但**今日清单不变**；想立刻用新池重抽要 `/ds reroll`。

## 六、数据文件

| 文件 | 内容 | 写入时机 |
| ---- | ---- | -------- |
| `daily.yml` | `date` + `items`（`MATERIAL:单价:额度` 列表），全服共享 | 零点自动重抽 / `/ds reroll` |
| `data.yml` | `players.<uuid>.<日期>.<MATERIAL>` 已售数量、`players.<uuid>.<日期>.__earned` 当日累计收益、`choices.<uuid>.<日期>` 选中的 Material 列表 | 出售 / 选择后延迟 100 ticks 合并写盘，关服强制落盘 |

`data.yml` 示例：

```yaml
players:
  00000000-0000-0000-0009-01f66567385a:
    2026-11-10:
      WHEAT: 12
      __earned: 36.0
choices:
  00000000-0000-0000-0009-01f66567385a:
    2026-11-10:
      - WHEAT
      - CARROT
```

- `players` 与 `choices` 两个根段平级，各自的日期键只保留最近 7 天（跨天重抽时清理）。
- `__earned` 是 1.2.1-r2 新增的累计字段。**旧 `data.yml` 没有该字段时**，插件会按当天全部已售物品与当前清单单价回放一次，作为兼容初值；之后每笔出售直接累加。
- 别在服务器运行时手改这三个文件，会被内存状态覆盖；先停服再改。

## 七、防刷与排错

| 机制 | 说明 |
| ---- | ---- |
| 只能卖选中的 5 种 | GUI / `sell` / `sellall` 三个入口统一走 `findEntry(p, material)`，未选中的一律拒绝 |
| 已选校验 | 未选满 5 种时三个出售入口全部拦截；`choices()` 只保留仍在今日清单里的项，`/ds reroll` 换物品后旧选择自动失效 |
| 每种额度 | `players.<uuid>.<date>.<MATERIAL>` 按天累计，重选不重置 |
| 每日收益上限 | `__earned` 与自选清单解耦；**`/ds choose clear` 重选或 `/ds reroll` 重抽都不会把已赚金额算丢** |
| 重抽一致性 | `/ds reroll` 会清空当天所有玩家选择、并关掉玩家手上打开的旧界面，避免界面显示旧物品却按新序号选择 |

| 现象 | 原因与处理 |
| ---- | ---------- |
| `/ds` 提示「还没选好今天的 5 种」 | 每天首次需先自选；基岩端 `/ds` 自动弹表单，Java 端 `/ds choose` 打开界面 |
| 基岩端点不了箱子 GUI | 1.2.2 起基岩端已不走箱子 GUI，`/ds` 直接弹原生表单；若仍弹 GUI 检查 Floodgate 是否安装 |
| 升级后仍显示 4 种候选 | 头号原因：服务器 `config.yml` 还是旧版 `items-per-day: 4`，只换 jar 没覆盖 config。1.2.3 起 `daily.yml` 旧清单会自动重抽，但前提是 config 已是 8 选 5；若仍异常可手动 `/ds reroll` |
| 提示「今日收购总收益已达上限」 | 单人当天已赚满 900 币；`/ds today` 可看「今日已赚 X/900」 |
| 打开界面后整理背包被取消 / 误卖 | 已修：插件只处理 GUI 顶栏点击，背包点击完全放行 |
| 物品名显示英文 | 新增 `pool` 键没在 Java 的 `ZH` 表补中文名 |
| 插件启动即被禁用 | 日志「未找到 Vault 经济插件」：装 Vault + EssentialsX，且确认有经济提供器注册 |
| 清单生成失败（日志警告） | 池太小或单价 / 额度过大导致 900 币预算装不下；降低 `max-per-item` 或 `price-float-max` |
