# 空间传送阵 SpacePortal 使用说明

适用于 **Java / 基岩互通服**（Paper/Spigot + Geyser/Floodgate）。
**默认关闭全部粒子与音效特效**，改用一个可自定义的「特殊物品」静态标记传送阵位置；需要时可在配置里一键恢复原特效。

## 一、安装

1. 服务器要求：
   - 旧版（`api-version: 1.20`，Java 17+）：Paper / Spigot 1.20.x（1.19~1.21 大部分版本可用）。
   - 26.3 版（`api-version: 26.3`）：Leaf 26.3 + **Java 25**。
2. 把 `SpacePortal-1.0.0.jar` 放入服务器 `plugins/` 目录，**重启服务器**（不要 `/reload` 换 jar）。
3. 互通服需已安装 Geyser + Floodgate。**26.3 版会自动改用基岩可见的 `ITEM` 模式**（无需改配置，见 6.2）；旧版（api 1.20）需手动把 `display-item.mode` 改为 `ARMOR_STAND`。
4. ⚠️ 替换 jar **不会覆盖**已有的 `plugins/SpacePortal/config.yml`。不过 `effects-enabled` 缺省即 `false`、`display-item.*` 缺省即默认值，26.3 版还在代码里做了**运行时 Geyser 自动降级**——旧配置即使写着 `ITEM_DISPLAY`，换 jar 后基岩端也会直接生效；想看到新配置注释可删除 `config.yml` 后重启（会丢掉手改过的参数，先备份）。

## 二、玩法流程

1. **建阵**：站到想放阵法的位置，执行：
   ```
   /csz create 主城
   /csz create 矿区
   ```
   - **管理员**（`spaceportal.admin`）建阵不占额度，记为公共阵法，所有人可见可用。
   - **普通玩家**（`spaceportal.create`）也能建阵，每人默认限 1 个，记为私人阵法并绑定归属者；上限由管理员通过 `/csz setlimit` 或界面控制。
2. **双向连接**（两点互通）：
   ```
   /csz link2way 主城 矿区
   ```
3. **使用**：玩家走进任意一个阵法范围，自动开始充能（动作栏显示文字进度），期间站在原地不动；充能完成后按 `cost-diamonds` 扣钻石并**立即传送**到相连阵法，落地后播放文字提示。默认**不再有**爆发粒子、时光穿梭隧道与任何音效。移动离开阵法会取消充能。
4. **图形界面**：输入 `/csz gui` 打开箱子界面。Java 版直接显示为箱子 GUI；基岩版经 Geyser 自动转换为原生箱子界面，双端同一套界面通用。

   - **主界面**（54 格）：0~44 列出你可见的阵法（自己的 + 公共的，管理员可见全部），45 创建阵法，48~50 管理员增减玩家建阵上限，52 费用信息，53 关闭。
   - **管理界面**（27 格）：在主界面**点击任意一个阵法图标**进入，可对该阵法单独操作 —— 4「连接到…」（聊天栏输入目标名，建立双向连接）、11「传送到该阵法」、13 阵法信息、15「删除该阵法」（需二次确认）、22「返回列表」。
   - **删除权限**：管理员可删除任意阵法（含公共阵法）；普通玩家只能删除自己名下的阵法。删除前按钮会变成红色「再次点击确认删除」，点其他按钮或关闭界面即取消。

   界面传送与走进阵法充能传送**使用同一套费用规则**：都按 `cost-diamonds` 扣钻石，免费权限（`spaceportal.free`）和创造/旁观免费同样生效。钻石不足时不会关闭界面、也不会传送，阵法图标上会直接标注本次消耗数量。

5. **随行实体传送（坐骑 / 宠物）**：充能传送与界面传送都会自动带上——
   - **坐骑**：玩家当前骑着的实体（马、驴、猪等）会一起传过去，落地后自动重新骑上；
   - **宠物**：检测半径（`pet-follow-radius`，默认 3 格）内**属于玩家本人**的已驯服宠物（马/狼/猫等 `Tameable`）会一起传送，落点分散在玩家周围 0.6 格避免重叠；
   - **归属校验**：半径内**其他人的宠物**不会随行，并提示「xxx 不是你的宠物，无法随行传送」；野生实体静默忽略；
   - **费用**：每个随行实体额外消耗 `cost-per-entity`（默认 **5**）颗钻石。总费用 = 基础 20 颗 + 随行实体数 × 5 颗，钻石不足会提示具体构成并取消传送；
   - 关闭：`config.yml` 中 `entity-follow-enabled: false` 即恢复只传玩家本人。

## 六、特效与特殊物品标记

### 6.1 默认：全部特效关闭

`effects-enabled: false`（默认）时：

- **不启动**地面法阵粒子任务，全服零粒子包、零 `spawnParticle` 调用；
- 充能开始/进度、钻石不足、充能完成、传送爆发、传送落地、取消充能的**所有音效**全部跳过；
- 落地后的「时光穿梭」定时任务不再创建；
- 传送前的 6 tick 蓄力停顿取消，充能满即传送；
- **保留**：动作栏文字进度、聊天提示、扣费规则、随行实体、GUI 传送、冷却。

想恢复原来的完整特效，把 `effects-enabled` 改 `true` 后 `/csz reload`，此时 `portal-radius` / `particle-interval-ticks` / `render-distance` / `tunnel-ticks` 等参数照常生效。

### 6.2 用特殊物品代替粒子法阵

特效关闭后阵法不再可见，插件在每个阵法中心上方放置一个展示实体，显示一个「特殊物品」作为静态标记：

**26.3 版默认 `AUTO`**：检测到 Geyser/Floodgate 时自动用 `ITEM`，纯 Java 服用 `ITEM_DISPLAY`。旧版（api 1.20）默认仍是 `ITEM_DISPLAY`。

| 模式 | 版本 | 说明 |
|---|---|---|
| `AUTO` | 仅 26.3（默认） | 自动选择：互通服 → `ITEM`，纯 Java 服 → `ITEM_DISPLAY` |
| `ITEM` | 仅 26.3 | **悬浮掉落物**：Geyser 有原生 `ItemEntity` 映射，Java / 基岩双端都可见。不可拾取、不消失、无重力、不写存档；物品合并 / 自然消失 / 玩家与生物拾取 / 漏斗吸取全部由事件拦截 |
| `ITEM_DISPLAY` | 两版 | 1.19.4+ 的 Item Display：Java 端最干净，无碰撞、静态、不写存档。**Geyser 没有该实体的基岩映射，基岩玩家看不到** |
| `ARMOR_STAND` | 两版 | 隐形 marker 盔甲架头顶戴物品，Geyser 支持；旧版互通服需手动切到这个模式 |

> ⚠️ **为什么基岩端看不到 Item Display**：Geyser 只实现了 `TextDisplayEntity`，没有 `ItemDisplayEntity`，实体注册表里也没有 `ITEM_DISPLAY` 的映射（该字符串只出现在 MCProtocolLib 的协议枚举里）。Java 端生成 Item Display 后，Geyser 不会向基岩客户端转发这个实体，基岩玩家**怎么刷新都看不到**——不是视距、粒子开关或客户端设置问题。
>
> 26.3 的运行时降级在 `SpacePortalPlugin#getDisplayMode()` 里完成：`saveDefaultConfig()` 不会覆盖服务器旧 `config.yml`，只改 jar 内默认配置对旧配置无效，所以必须在代码里兜底。`/csz item`（无参数）可查看「配置模式 → 实际模式」以及是否检测到 Geyser。

展示实体带 PDC 标记（`portal_display` 记录阵法名、`portal_display_mode` 记录创建时的模式）。26.3 版每 5 秒做一次**全服 PDC 扫描去重**：按阵法名分组，每个阵法严格只保留一个有效且模式匹配的实体，多余的、孤儿的和旧模式残留的全部删除，缺失的才补建；因此即使实体被合并、被清理插件移除、被玩家挤走或多次 `/csz reload`，也**不会堆出多个物品**。掉落物被挤离中心超过 0.75 格时才纠正一次位置，不产生周期发包。整个过程**没有粒子、没有音效**。

`/csz item`（无参数）会显示「标记实体数 / 阵法数」，正常情况下两个数字相等；不等时执行 `/csz item refresh` 立即去重。

### 6.3 自定义特殊物品（支持数据组件）

默认是回响碎片 + 名称「✦ 空间传送阵」。想换成带附魔、自定义模型或任意数据组件的物品：

```bash
# 1) 拿到任意特殊物品，例如带组件的木棍
/give @s minecraft:stick[minecraft:enchantments={levels:{minecraft:knockback:10}},minecraft:custom_name='"空间钥匙"']

# 2) 手持它，设为全局阵法标记（整件 ItemStack 序列化进 override.yml，重启保留）
/csz item set

# 3) 给自己 / 玩家发一份同样的物品（配合 use-as-trigger 当凭证用）
/csz item give

# 其他
/csz item            # 查看当前物品、展示模式、特效与凭证状态
/csz item reset      # 恢复 config.yml 默认物品
/csz item refresh    # 手动重建所有标记实体
```

### 6.4 物品凭证模式（可选）

`display-item.use-as-trigger: true` 时，玩家必须**主手持有**该特殊物品，踩进阵法才会开始充能；没拿物品会提示一次。匹配用 `ItemStack#isSimilar`（忽略数量），并辅以「同材质 + 同显示名」兜底，兼容数据组件序列化差异。默认 `false`：物品只作静态标记，踩阵传送逻辑不变。

## 七、卡顿调优（仅在 `effects-enabled: true` 时有意义）

默认关闭特效后**不再有任何粒子网络包**，本节只在恢复特效后适用。粒子卡顿的本质是**网络包数量**：每一次 `spawnParticle` 调用都是一个独立数据包，发给附近所有玩家。按优先级依次调：

1. 调大 `particle-interval-ticks`（默认 4）：4 → 6 立刻省 1/3，→ 10 帧率再降一半。
2. 调小 `render-distance`（文档默认 24，本服实际 40.0）：客户端粒子渲染距离有限，设太大只是白发包。
3. 调小 `portal-radius`：半径不影响粒子点数，但影响客户端的粒子绘制面积。

插件已做的性能优化：同位置点多颗粒用 `count` 参数一次发出（1 个包渲染多颗粒子，视觉密度不降）；色相→RGB 结果全局缓存，每帧不重复新建 `Color`；玩家可见性按 `world.getPlayers()` 过滤。

## 八、常见问题

- **换 jar 后配置没变、也没看到新配置项**：`saveDefaultConfig()` 不覆盖已有文件，但缺省值即「关特效 + 物品标记」，功能已生效；想看新注释就备份后删 `config.yml` 重启。
- **基岩玩家看不到物品标记**：Geyser 没有 Item Display 的基岩实体映射，这是根因，不是视距或客户端问题。
  - **26.3 版**：换上新版 jar 后**重启服务器**即自动降级为 `ITEM`（悬浮掉落物），旧 `config.yml` 不用改；用 `/csz item`（无参数）确认显示 `ITEM` 且「已检测到 Geyser/Floodgate」。若显示仍是 `ITEM_DISPLAY`，说明 `display-item.geyser-fallback` 被设成了 `false`，改回 `true` 后 `/csz reload`。
  - **旧版（api 1.20）**：把 `display-item.mode` 改成 `ARMOR_STAND` 后 `/csz reload`。
- **同一个阵法变成很多个物品**：旧版只靠内存里的 UUID 表判重，掉落物一旦被合并、被清理插件移除、区块卸载或热重载，UUID 失效就补建一个，而旧实体没被清掉，于是越堆越多。26.3 新版已改为按 PDC 标记全服扫描去重（见 6.2）：换 jar **停服完整重启**后，第一次扫描（启动即执行，之后每 5 秒）就会把多余实体删干净；不想重启也可先执行 `/csz item refresh`。用 `/csz item` 确认「标记实体数 / 阵法数」相等。若重启后仍反复增多，说明有清理插件在不停删掉落物，把它加入排除列表，或把 `display-item.mode` 改成 `ARMOR_STAND` 后 `/csz reload`（盔甲架不会被合并、不会被推动）。
- **标记实体被清理插件清掉**：插件每 5 秒自动补齐；若反复被清，把 Display / ArmorStand / 掉落物加入清理插件的排除列表（26.3 互通服现在是 `ITEM` 掉落物）。
- **标记物品被漏斗吸走 / 玩家捡走**：`ITEM` 模式已设不可拾取 + 无限寿命，并拦截 `InventoryPickupItemEvent`；若装了不走 Bukkit 事件的清理插件，仍需按上一条加排除列表。
- **想让阵法完全隐形**：`display-item.enabled: false`，此时只能靠 `/csz gui` 或坐标定位阵法。
- **`/csz item set` 后重启物品变了**：物品以 Bukkit 序列化存进 `override.yml`；若手工编辑过该文件导致格式损坏，删掉 `display-item:` 段即可回退到默认物品。
- **钻石被扣但没传送**：不会发生——费用在传送执行前一刻才扣除，余额不足会直接提示。
- **跨世界传送**：支持，两个阵法可以在不同世界，目的地世界需已加载。
- **源码**：两个 Maven 工程分别在 `SpacePortal/`（旧版）与 `升级26.3版本/SpacePortal/`，图案在 `EffectController.java`，物品标记在 `display/PortalDisplayManager.java`。
