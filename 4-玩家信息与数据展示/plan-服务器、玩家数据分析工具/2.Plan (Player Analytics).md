### Plan (Player Analytics) 完整配置与使用教程

Plan 是一款功能极其强大的 Minecraft 服务器数据分析工具，它能自动收集服务器的各种运行数据，通过内置的 Web 仪表盘以可视化图表的形式展示给你。无论是玩家行为分析、服务器性能监控还是留存率统计，Plan 都能轻松胜任。

---

### 📥 下载与安装

#### 环境要求

- **Java**: 11 或更高版本
- **服务端**: Spigot / Paper / Folia / Fabric / Sponge / BungeeCord / Velocity 等主流平台均支持
- **额外端口**: 需要对外开放一个端口（默认 8804）用于访问 Web 面板

#### 安装步骤

1. 前往 GitHub Releases 页面下载最新版本的 `Plan.jar`：
2. 将 `Plan.jar` 放入服务器的 `plugins` 文件夹中
3. 启动或重启服务器，Plan 会自动在 `plugins/Plan/` 目录下生成配置文件和数据库
4. 启动完成后，在浏览器中访问 `http://你的服务器IP:8804` 即可打开 Web 仪表盘

### ⚙️ 核心配置

Plan 的主配置文件位于 `plugins/Plan/config.yml`，以下是各关键配置项的详细说明。

#### Web 服务器设置

```yaml
Webserver:
  # Web 面板监听的端口，默认 8804
  Port: 8804

  # 如果你想通过域名访问，可以开启此项
  Alternative_IP:
    Enabled: false
    # %port% 会被自动替换为上方配置的端口号
    Address: 'play.yourserver.net:%port%'

  # 是否启用 HTTPS（需要 SSL 证书）
  # 启用后访问面板需要输入账号密码
  Security:
    SSL_Certificate:
      Enabled: false
      # Keystore 文件路径
      Key_Store_Path: 'Keystore.p12'
      # Keystore 密码
      Key_Store_Password: 'password'
      # 别名
      Alias: 'alias'
```

> **提示**：如果你的服务器没有建站经验，可以不开启 SSL，直接修改端口号来规避玩家访问。Plan 是"只读"工具，只能获取数据而不能控制服务器，不加密也不会有安全问题。

#### 数据库设置

```yaml
Database:
  # 数据库类型：SQLite（默认，零配置）或 MySQL
  Type: MySQL   # 本服实际：MySQL（Velocity 群组必须用 MySQL，所有子服连同一个库）

  # MySQL 配置（跨服网络必须使用 MySQL）
  MySQL:
    Host: 'localhost'
    Port: 3306
    Database: 'Plan'          # 库名区分大小写，必须先建好，见下方流程
    User: 'root'
    Password: 'xxx'    # 真实密码不写入文档，按服务器实际配置填写
    # 连接串附加参数
    Launch_options: '?rewriteBatchedStatements=true&serverTimezone=UTC'
    # 连接池设置
    Max_connections: 8
```

- **单服模式**：使用默认的 SQLite 即可，无需额外配置
- **群组模式**（BungeeCord/Velocity）：必须使用 MySQL，所有子服连接同一个数据库，数据会在代理端自动聚合

##### 配置 MySQL 完整流程（本服实测）

1. **先在 MySQL 建库**（缺了这步，Plan 连不上会自动降级 SQLite，配置等于没生效）：

```sql
CREATE DATABASE Plan CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 改 `plugins/Plan/config.yml`：`Type: MySQL` + 连接信息，**库名与上一步完全一致**（`Plan`）
3. **重启服务器**（切库必须重启；`/plan reload` 只重载配置，不切库）
4. 验证生效：
   - 启动日志不再出现 `SocketException / ConnectException`（排除更新检查报错后）
   - `SHOW TABLES FROM Plan;` 能看到 users / actions / ping 等表（Plan 自动建表）
   - 打开 Web 面板 `http://plan.mchappyhut.club:8804` 数据正常

> **降级行为**：MySQL 连接失败时 Plan 不会崩，而是自动退回 SQLite（`plugins/Plan/database.db`）继续记录——所以"配了 MySQL 但网页还正常"≠"MySQL 生效了"，要用上面第 4 步核对。

#### 数据收集设置

```yaml
Data_gathering:
  # 是否收集玩家的地理位置信息（国家级别）
  Geolocations: true

  # 是否收集服务器性能数据（TPS、CPU、内存等）
  Server_performance: true

  # 是否追踪玩家在世界中的活动时间分布
  World_time_tracking: true

  # AFK 判定阈值（玩家超过此时间无操作则判定为 AFK）
  # 实际值：Time: 3, Unit: MINUTES（即 180 秒）
  AFK_threshold:
    Time: 3
    Unit: MINUTES

  # 是否记录玩家的 Ping 值变化
  Ping: true

  # 是否记录玩家使用的客户端信息
  # 如 Lunar Client、Badlion、原版等
  Client_info: true
```

#### 活动指数设置

```yaml
Analysis:
  # 活动指数计算阈值
  # 如果玩家每周在线时间达到此值，活动指数约为 3
  # 达到 2 倍此值，活动指数约为 4
  # 实际值：Playtime_threshold Time: 30, Unit: MINUTES（30 分钟）
  Activity_index:
    Playtime_threshold:
      Time: 30
      Unit: MINUTES
```

活动指数是 Plan 的核心指标之一，用于衡量玩家的活跃程度，范围从 0 到 5，数值越高代表越活跃。

### 📊 Web 仪表盘功能详解

打开 Web 面板后，你会看到一个专业的数据仪表盘，主要分为以下几个板块：

#### 概览页面

- **实时在线人数图**：显示当前及过去数小时的玩家数量变化
- **服务器性能**：实时 TPS、CPU 占用率、内存使用情况
- **今日数据**：今日新增玩家、回归玩家、总在线时长等关键指标

#### 玩家分析

- **玩家列表**：列出所有记录过的玩家，支持按名称、UUID、权限组等筛选
- **玩家详情页**：点击任意玩家可查看：
  - 每次登录/登出的时间和在线时长（会话记录）
  - PVP/PVE 击杀与死亡数据
  - 基于 IP 的地理位置（国家/城市）
  - 客户端信息（品牌、游戏版本、分配内存等）
  - 活动时间热力图（什么时段最活跃）

#### 服务器分析

- **性能图表**：以天/周/月为单位查看 TPS、CPU、内存的历史趋势
- **活动日历**：热力图展示一年中每天的玩家活跃程度
- **留存率分析**：新玩家的次日、第3日、第7日、第30日回归比例

#### 查询功能

支持使用特定语法提取数据，例如：

- `players online:100-200` — 查找在线时长在 100~200 小时的玩家
- `deaths:1000-` — 查找死亡次数超过 1000 次的玩家

可通过 `/plan search help` 查看完整的查询语法。

#### 网络视图（群组模式）

在 BungeeCord/Velocity 代理端安装 Plan 后，此页面会展示整个网络的数据聚合视图，可以清晰看到玩家在不同子服之间的流动情况。

### 🔌 PlaceholderAPI 集成

Plan 完美支持 PlaceholderAPI，可以在 TAB、记分板等插件中调用 Plan 的数据。

#### 常用占位符

| 占位符                             | 说明               |
| ---------------------------------- | ------------------ |
| `%plan_player_times_online%`       | 玩家总在线时长     |
| `%plan_player_kills_player%`       | 玩家 PVP 击杀数    |
| `%plan_player_deaths%`             | 玩家死亡次数       |
| `%plan_player_activity_index%`     | 玩家活动指数       |
| `%plan_server_players_online%`     | 服务器当前在线人数 |
| `%plan_server_unique_players_day%` | 今日独立玩家数     |
| `%plan_server_new_players_day%`    | 今日新玩家数       |
| `%plan_server_tps%`                | 服务器当前 TPS     |

#### 使用步骤

1. 确保已安装 PlaceholderAPI 插件
2. 在 TAB 或记分板配置中直接使用上述占位符即可

### 🌐 群组模式配置（BungeeCord/Velocity）

如果你运营的是跨服网络，Plan 支持将所有子服的数据聚合到一个面板中：

1. **在代理端**（BungeeCord/Velocity）安装 Plan 并配置 MySQL
2. **在每个子服**也安装 Plan，同样连接同一个 MySQL 数据库
3. 子服检测到代理端存在后，会自动关闭自身的 Web 服务器以节省资源
4. 只需访问代理端的 Web 面板即可看到所有子服的聚合数据

### 💡 实用技巧

#### 性能优化

- Plan 本身性能开销很低，但如果服务器人数特别多，可以适当关闭不需要的数据收集项（如地理位置、客户端信息）
- 使用 MySQL 替代 SQLite 可以提升大数据量下的查询性能

#### 数据导出

- Web 面板的图表支持导出为 JSON 格式
- 可以通过 `/player/<name>/raw` 和 `/server/<name>/raw` 获取原始数据链接

#### 与 TAB 插件联动

结合 TAB 插件，可以在玩家列表中显示 Plan 提供的数据：

```yaml
tabsuffix: ' &7| 在线: %plan_player_times_online%'
```

#### 机器人集成

Plan 支持 Discord 和 Telegram 机器人集成，可以将服务器上线通知、性能警报等信息推送到社区频道中，相关配置在 `plugins/Plan/` 目录下的对应配置文件中。
