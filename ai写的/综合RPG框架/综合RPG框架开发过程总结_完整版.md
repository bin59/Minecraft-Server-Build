# 综合RPG框架 · 数据包完整开发过程记录

> 目标服务器：Leaf 1.21.11（Paper 分支）Java/基岩互通服
> 最终交付：`world\datapacks\rpg_framework`（143 个文件）+ 备份压缩包（71.8 KB）
> 适配版本：Minecraft Java 1.21.11，数据包格式 94.1
> 本文档分两部分：第一部分为初版（指令版）开发记录，第二部分为界面版扩展开发记录

---

# 第一部分：初版搭建（指令交互版）

## 阶段一：需求接收与环境侦察

### 步骤 1：加载编码技能
接到"写一个角色扮演游戏数据包"需求后，先加载 `coding` 技能获取编码规范指导，避免实现方式出错。

### 步骤 2：侦察服务器目录结构
扫描服务器根目录，确认关键信息：
- 服务端核心：`leaf-1.21.11-174.jar`（Leaf 是 Paper 的分支）
- 使用 authlib-injector + YggdrasilOfficialProxy（外置登录/互通配置）
- 存在 `world`、`world_nether`、`world_the_end` 三个世界目录

### 步骤 3：确认数据包安装位置
查看 `world` 目录，确认已存在 `datapacks` 文件夹——数据包必须放在主世界的 `datapacks` 目录才会被加载。

### 步骤 4：读取 server.properties
确认服务器配置细节：
- `level-name=world`（主世界名称，决定数据包放置路径）
- `function-permission-level=2`（函数以 2 级权限执行，可执行 give/effect/tp 等管理指令）
- 生存模式、白名单开启、端口 55551

## 阶段二：技术调研

### 步骤 5：查询 1.21.11 数据包格式版本号
通过维基确认：
- **1.21.11 数据包格式 = 94.1**
- 自 25w31a 起，`pack.mcmeta` 改用 `min_format`/`max_format` 字段（数组形式 `[主版本, 次版本]`）
- 最终写法：`"min_format": [94, 0], "max_format": [94, 99]`

### 步骤 6：确认新版目录命名规范
1.21 起目录全部单数化（旧名会导致函数无法加载）：
- `functions` → `function`
- `loot_tables` → `loot_table`
- `tags/functions` → `tags/function`

### 步骤 7：确认基岩互通兼容性原理
数据包是纯服务端逻辑（计分板 + 函数 + 指令），基岩玩家通过 Geyser 接入后同样执行服务端指令：
- 所有交互统一走 `/trigger` 指令（非 OP 玩家可用，基岩玩家可手动输入）
- 经搜索核实：`/trigger` 是唯一允许普通玩家修改自己触发器计分板的指令

## 阶段三：需求澄清

### 步骤 8：向用户确认设计方向
用选项卡询问两个关键问题（避免方向错误返工）：
- **RPG 类型** → 用户选择：综合大型框架
- **功能规模** → 用户选择：完整版

据此确定 8 大系统的设计范围：职业、等级、技能、任务、经济、传送、BOSS、排行榜+管理。

## 阶段四：核心框架搭建

### 步骤 9：创建数据包元数据
写入 `pack.mcmeta`，格式版本 94，描述使用彩色文本。

### 步骤 10：创建函数标签（挂载点）
- `data/minecraft/tags/function/load.json` → 启动/重载时执行 `rpg:load`
- `data/minecraft/tags/function/tick.json` → 每游戏刻执行 `rpg:tick`

### 步骤 11：编写加载函数 `rpg:load`
建立全部计分板体系：
- 核心属性：`rpg.level`/`rpg.exp`/`rpg.exp_need`/`rpg.gold`/`rpg.class`
- 击杀统计：`rpg.kills`（准则 `totalKillCount`）+ `rpg.k_done`（防重复结算）
- 任务统计：杀僵尸/拾铁锭/杀骷髅三个准则目标 + 基准值与状态板
- 16 个 `trigger` 类型触发器目标（玩家指令入口）
- 展示槽位：侧边栏等级榜、Tab 列表金币
- 创建 BOSS 血条 `rpg:boss`（最大 200，默认隐藏）

### 步骤 12：编写主循环 `rpg:tick`
每刻执行的分发中心：新玩家初始化 → 触发器分发 → 击杀结算 → 升级检测 → 冷却递减 → 魔杖右键检测 → 任务轮询 → 跨天检测 → BOSS 监控 → 每秒重新启用触发器。

### 步骤 13：编写卸载函数 `rpg:uninstall`
完整清理：删除血条、移除标签、移除属性修饰符、删除全部计分板、清除传送点存储。

## 阶段五：玩家成长模块

### 步骤 14：新玩家初始化 `rpg:player/join`
初始化计分（等级1/金币100/经验0）、发放新手礼包（面包×16、技能魔杖）、大标题欢迎、引导选职业。

### 步骤 15：击杀结算 `rpg:player/kill_diff`
`totalKillCount` 是累计值，用"本刻总数 − 已结算数"算出本刻新增击杀，支持一帧多杀；每杀 +1 经验 +1 金币。

### 步骤 16：升级系统（三函数协作）
- `level_check`：每刻检查，支持一次击杀连升多级（递归）
- `do_levelup`：扣经验、升级、+50金、回血特效、全服广播
- `calc_need`：升级公式 `20 + (等级-1) × 12`

### 步骤 17：等级被动属性
10 级起每 2 级 +1 最大生命（上限 +10），通过 `attribute modifier` 实现，可精确移除不污染原始属性。

## 阶段六：职业系统

### 步骤 18：职业菜单与四职业实现
| 职业 | 被动加成 | 实现方式 |
|---|---|---|
| 战士 | 攻击+3、生命+4 | `attack_damage`/`max_health` 修饰符 `add_value` |
| 弓箭手 | 移速+15% | `movement_speed` 修饰符 `add_multiplied_total` |
| 法师 | 技能冷却-30% | 技能函数内检测标签，冷却打七折 |
| 牧师 | 持续回血 | 主循环每 20 tick 挂 2 秒再生效果 |

另有 `reset_self` 供管理员重置职业。

## 阶段七：技能系统

### 步骤 19：双入口设计
右键魔杖（`minecraft.used:carrot_on_a_stick` 准则）+ `/trigger rpg.skill`，统一走冷却判断。

### 步骤 20：四职业技能实现
- **冲锋怒吼**：8 秒力量+1、抗性+1，周围敌人短暂悬浮震飞
- **箭雨**：头顶召唤 6 支不同 `Motion` 的箭（`pickup:0b` 不可拾取）
- **圣火流星**：视线前方生成 3 个小型火球垂直坠落（不破坏地形）
- **圣光普照**：治疗 8 格内所有玩家

## 阶段八：任务系统

### 步骤 21：三条可重复任务线 + 三态状态机
三态设计：`0 未接取 → 1 进行中 → 2 已达标待交付 → 0`。接取时记录统计基准值，进度 = 当前统计 − 基准，避免历史数据污染。共 16 个函数。

## 阶段九：经济系统

### 步骤 22：金币商店
10 种商品，每函数结构统一：余额检查 → 扣款 → 发货 → 提示+音效。药水用 1.21 物品组件语法 `potion[minecraft:potion_contents={potion:"..."}]`。

### 步骤 23：玩家转账
转给"16 格内最近的玩家"（避开基岩版无法解析玩家名的难题），用标签标记付款方完成双向扣加款。

### 步骤 24：每日签到
用游戏内天数（`#day` 计数）限制每天一次，主循环检测 `daytime` 回绕。

## 阶段十：传送系统

### 步骤 25：存储方案设计
坐标存入 `storage rpg:warps`（w1/w2/w3），每点含 x/y/z/dim 四字段。

### 步骤 26：管理员设置传送点
站在目标位置执行，读取玩家 `Pos[0..2]` 写入存储；`nbt={Dimension:-1/1}` 判断下界/末地。

### 步骤 27：函数宏实现跨维度传送
```
$execute in $(dim) run tp @s $(x) $(y) $(z)
```
一行宏解决"动态维度+动态坐标"，避免 27 种组合分支。

## 阶段十一：BOSS 战

### 步骤 28：召唤逻辑
门槛：等级≥5 且金币≥300；全服仅一只（`#boss_alive` 全局锁）；200 血强化僵尸，抗火+迅捷永久效果，全套下界合金装备（掉落率归零）。

### 步骤 29：血条同步与死亡结算
每刻同步 `Health` 到血条，水下防卡；击杀后全服 +500金 +300经验。

## 阶段十二：版本兼容性修正（最费工的一环）

### 步骤 30：修正属性修饰符语法
1.21.5+ 语法变化：`modifier add <id> <值> <运算>`，运算名改为 `add_value`/`add_multiplied_total`。

### 步骤 31：修正实体 NBT 混合命名
查阅实体格式文档确认：保持大写的 `Pos`/`Motion`/`Health`/`Tags`/`CustomName`，改为小写的 `equipment`/`attributes`/`active_effects`/`drop_chances`。

### 步骤 32：修正投射物字段
火球的 `power` 字段已移除，箭雨和圣火流星全部改用 `Motion`。

### 步骤 33：修正文本组件字段名
`clickEvent` → `click_event`，`hover_event` 的 `contents` → `value`。

### 步骤 34：修正法师技能方向性
`Motion` 是世界坐标不跟随朝向，改为"视线前方生成 + 垂直坠落"。

### 步骤 35：BOSS 掉落保护
`drop_chances` 全槽位 0.0 + `CanPickUpLoot:false`。

# 第二部分：界面版扩展开发记录

> 需求：丰富服务器玩法内容 + 减少指令使用、多使用界面 + 支持基岩版

## 阶段一：界面方案调研

### 步骤 39：调研 1.21.11 原生弹窗系统（Dialog）
维基核实关键信息：
- 1.21.6 引入 `dialog` 注册表，数据包可定义 `.json` 弹窗界面
- 五种类型：`notice`（单按钮）、`confirmation`（确认/取消）、`multi_action`（多按钮列表）、`server_links`、`dialog_list`（跳转列表）
- 动作类型：`run_command`、`suggest_command`、`show_dialog`（弹窗跳转）、`dynamic/run_command`（带输入宏模板）
- 输入控件：文本框、勾选框、单选、数字滑块（`number_range`）
- **关键能力**：可通过 `#minecraft:pause_screen_additions` 标签挂进 ESC 暂停菜单，通过 `#minecraft:quick_actions` 挂进快捷动作键——实现零指令打开
- 关键限制：弹窗文本不支持 score/selector/NBT 组件（动态数据显示不了，只能放静态内容）

### 步骤 40：确定双通道交互架构
基岩版客户端不支持 Dialog 协议，弹窗只有 Java 版能显示。设计双通道：
- **Java 版**：ESC 暂停菜单 / 快捷动作键 / 右键道具 → 图形弹窗，零指令
- **基岩版**：右键道具 / 聊天按钮 → 聊天菜单（tellraw 按钮基岩版可点击），`/trigger` 指令兜底

## 阶段二：图形界面开发（10 个弹窗）

### 步骤 41：主菜单 `dialog/main.json`
`multi_action` 类型，13 个按钮（职业/商店/任务/传送/抽奖/签到/BOSS/精英/转账/排行/角色/帮助/基岩指南），2 列布局，按钮带悬浮提示，`show_dialog` 跳转子弹窗、`run_command` 执行触发器指令，`pause: false`（不暂停游戏）。

### 步骤 42：职业选择弹窗 `class_select.json`
`body` 中用 `minecraft:item` 元素展示四职业图标+属性说明，4 个按钮分别执行 `trigger rpg.pick set 1~4`。

### 步骤 43：商店弹窗 `shop.json`
10 个商品按钮，关键设计：`"after_action": "none"`——点击购买后弹窗保持打开，支持连续购物。

### 步骤 44：任务面板弹窗 `quest_board.json`
12 个按钮（3 普通任务 + 3 每日任务，各含接受/交付），`after_action: none` 保持打开。

### 步骤 45：传送弹窗 `warp.json`
3 个传送按钮，未设置时服务端函数会提示联系管理员。

### 步骤 46：BOSS 确认弹窗 `boss_confirm.json`
`confirmation` 类型，防止误触浪费 300 金。

### 步骤 47：抽奖弹窗 `lottery.json`
`confirmation` 类型，正文公示完整奖池概率（100金50%/200金25%/500金10%/附魔金苹果5%/谢谢惠顾10%）。

### 步骤 48：转账弹窗 `pay.json`
核心亮点：`number_range` 数字滑块输入（1~10000，步长10）+ `dynamic/run_command` 宏模板 `trigger rpg.pay set $(amount)`——把原来"手动输入金额指令"变成拖滑块。

### 步骤 49：玩法帮助弹窗 `help.json`
`notice` 类型，7 段 `plain_message` 汇总全部系统。

### 步骤 50：基岩版指南弹窗 `bedrock_guide.json`
4 个 `suggest_command` 按钮（角色面板/任务进度/释放技能/排行榜），点击自动把指令填入聊天框，基岩玩家只需按发送。

## 阶段三：弹窗入口挂载

### 步骤 51：挂进暂停菜单
创建 `data/minecraft/tags/dialog/pause_screen_additions.json`，加入 `rpg:main` 和 `rpg:bedrock_guide`——按 ESC 就能打开。

### 步骤 52：挂进快捷动作键

## 阶段四：新增玩法开发

### 步骤 54：幸运抽奖系统
- `rpg.lottery` 触发器 + 入口函数：扣 50 金 → `random value 0..99` 生成随机数 → 按区间分发奖项

### 步骤 55：精英入侵挑战

- `elite_clear`：全部击败 → 全服 +300金 +200经验 + 胜利演出

### 步骤 56：每日任务（3 条）

更新 `economy/new_day`：跨天时将三个每日任务状态归零，广播刷新提醒。

## 阶段五：成就系统

### 步骤 59：创建成就树（11 个定义）
全部使用 `minecraft:impossible` 准则（由函数手动授予），根节点 `rpg:root` 定义标签页背景：
- 根：踏入RPG世界（金块背景）
- 主线链：选择职业 → 5级 → 10级 → 20级 → 30级 → 50级（frame 从 task 逐级升到 challenge）
- 支线：初露锋芒（首次技能）、任务达人（累计5任务）、屠龙者（击败BOSS）、精英克星（平息入侵）、富甲一方（10000金）

### 步骤 60：成就授予接线
- `player/join` → 授予根成就
- `class/pick` → 选择职业成就
- `skill/cast` → 首次技能成就（用 `rpg.cd matches 1..` 判断技能确实释放成功）
- `quest/complete_common`（新建）→ 任务完成计数，满 5 次授予任务达人
- `mob/boss_death` / `mob/elite_clear` → 全服授予对应成就
- `tick` 主循环 → `rpg.gold matches 10000..` 自动授予富甲一方

## 阶段六：右键道具入口与基岩版兼容

### 步骤 61：冒险指南道具设计
新手礼包新增「冒险指南」，右键打开主菜单（聊天菜单+弹窗双通道）。

### 步骤 62：第一版方案（被废弃）
最初尝试：指南用时钟 + `minecraft.used:minecraft.clock` 计分板，魔杖和指南共用 `stick/use` 分发，用 `items entity ... custom_data~{rpg_guide:1b}` 组件匹配区分。
**问题发现**：`items` 命令的 `custom_data~` 谓词语法在 1.21.11 存在兼容风险，且时钟右键会被原版地图功能干扰。

### 步骤 63：最终方案（双物品区分）
改用两种不同钓竿，各自有独立的 `minecraft.used` 准则，物理区分最可靠：
- 技能魔杖 = 胡萝卜钓竿（`rpg.stick` 计分板）
- 冒险指南 = 诡异菌钓竿（`rpg.guide` 计分板）
- 删除整个 `stick/` 分发目录，主循环改为两条独立监听
- 右键统计准则是原版机制，Java/基岩双端都能可靠计数

# 关键设计决策对照表（两轮合并）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 玩家交互入口 | Dialog 弹窗 + 聊天按钮 + `/trigger` 三通道 | 弹窗服务 Java 版，聊天按钮服务基岩版，指令兜底 |
| 弹窗入口挂载 | 暂停菜单 + 快捷动作键 + 右键道具 | 零指令打开，符合"多用界面"需求 |
| 转账金额输入 | `number_range` 滑块 + `dynamic/run_command` 宏 | 消除手动输入指令 |
| 商店连续购物 | `after_action: none` | 点击后弹窗不关闭 |
| 双端右键道具 | 两种不同钓竿 + 独立 `minecraft.used` 准则 | 避开 `custom_data` 谓词兼容风险，原版机制双端可靠 |
| 基岩版弹窗不可见 | 右键道具双通道输出（聊天菜单+弹窗） | 同一操作双端都有响应 |
| 每日任务防重复领取 | 第四态 `3=今日已完成` + 跨天归零 | 状态机原生扩展 |
| 成就系统 | `impossible` 准则 + 函数手动授予 | 成就逻辑全在函数中，无需监听游戏事件 |
| 抽奖公平性 | `random value` 命令 + 概率公示在弹窗正文 | 原版随机数，概率透明 |
| 界面文字 | 纯中文，无 emoji | 游戏默认字体渲染不了 emoji |
| 弹窗动态数据 | 不放（用聊天面板查） | Dialog 不支持 score/selector 组件 |

# 遗留说明与已知限制

1. **弹窗不显示动态数据**：角色金币、任务进度等实时数据只能在聊天面板（`/trigger rpg.stats`、`/trigger rpg.quest`）查看，这是 Dialog 系统的固有限制。
2. **基岩版无图形弹窗**：Geyser 不转发 Dialog，基岩玩家走聊天按钮通道，功能完全一致，只是交互形式不同。
3. **旧存档玩家无指南道具**：界面版上线前进服的玩家没有"冒险指南"，可通过 `/give <玩家> minecraft:warped_fungus_on_a_stick` 补发，或按 ESC 打开。
