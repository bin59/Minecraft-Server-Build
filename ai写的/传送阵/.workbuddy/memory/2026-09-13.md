## 环境备忘

## SpacePortal：粒子特效卡顿优化（用户反馈"粒子太卡，简洁一点"）

- 根因：卡顿本质是**网络包数量**而非粒子数 —— 每次 `spawnParticle` = 一个包发给附近所有玩家。
  原 `drawPortalCircle` 每帧约 190 次调用（光柱 42 + 三环 64 + 六芒星 48 + 符文环 32 + 上升微光 5），
  10 Hz（每 2 tick）→ 单阵法约 1900 包/秒，多阵法叠加直接爆。
  另有隐藏开销：`getNearbyEntities` 每帧对每个阵法扫描全部实体。
- 优化手段（每阵法每帧包数 190 → 约 58，再叠加降频，整体约为原来的 1/9）：
  1. **画面精简**：去掉双层外环中的一层、符文环、上升微光；光柱 14 层×3 点 → 稀疏单点；六芒星每边 8 点 → 4 点。
  2. **count 参数聚合**：外环每点 count=2 + 小 offset，1 个包渲染多颗粒子，视觉密度不降反增。
  3. **Color 缓存**：`ConcurrentHashMap<Integer, Color>` 按整数度数缓存 HSB→RGB 结果（原来每帧新建 ~190 个 Color）。
  4. **可见性判定**：`getNearbyEntities` → `world.getPlayers()` + distanceSquared，避免扫描怪物/掉落物。
  5. **降频可配置**：新增 `particle-interval-ticks`（默认 4，原为固定 2 tick）。
     `SpacePortalPlugin` 持有 `effectTaskHandle`，`applyConfig()` 末尾调 `startEffectTask()` 重建任务 → **改配置 /csz reload 即时生效，无需重启**。
     注意 task delay 5L 保证 run 时 portalManager 已初始化。
  6. 隧道特效每 2 tick 一帧（`TUNNEL_FRAME_TICKS=2`，frames = tunnelTicks/2，总时长不变）；
     `render-distance` 默认 40 → 24（超出客户端渲染距离的包是白发的）。
- 文档：`空间传送阵使用说明.md` 新增「七、卡顿调优」章节（原七改八），参数表补 `particle-interval-ticks`。
